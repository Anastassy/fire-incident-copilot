# Производственный пакет S6 · Firewatch, 120 секунд

Здесь находятся исходники слайдов, озвучки, монтажа и очищенные манифесты для [сценария S6](../../VIDEO_SCRIPT.md). Пакет предназначен для проверки и повторной сборки: аудио, видео, изображения, презентации, ключи и внутренние инструменты сторонних плагинов в Git не включены. Скрипт монтажа включён; итоговые проверки записаны в `verification.reference.json`.

## Что уже изготовлено

**23 английские реплики** штатным голосом ElevenLabs **Daniel — Steady Broadcaster**, British English, `premade`, voice ID `onwK4e9ZLuTAKqWW03F9`. Модель — `eleven_multilingual_v2`, скорость `1.0`. Авторские учебные реплики оператора D08 и D13 произнесены тем же голосом; это не реальные радиопереговоры и не клонирование голоса.

Фактическая длительность 23 финальных WAV суммарно составляет **90.274 секунды**. Вместе с монтажными паузами дикторский stem занимает ровно **120.000 секунд**. Каждая реплика измерена `ffprobe` и помещается в своё окно S6. Текст сокращался перед повторной генерацией; слова не обрезались, скорость и высота голоса не менялись. В шести файлах убрана только подтверждённая конечная тишина, с запасом более 75 ms после последнего символа речи по alignment. Оригинальные take-файлы сохранены в отдельном наборе медиа.

В `narration-timeline.reference.json` записаны измеренные длительности, расположение реплик, SHA-256 финальных WAV и выполненные проверки. Это запись **конкретной готовой генерации**, а не обещание, что новый TTS-запрос даст ту же длительность или байты. Все пути в манифестах относительные; корень — внешний каталог медиа, указанный через `--output-dir`.

## Состав

| Файл | Назначение |
|---|---|
| `narration-plan.json` | Окна S6, финальный английский текст, голос и настройки |
| `generate_narration.py` | Платная генерация только явно перечисленных реплик через ElevenLabs API |
| `finalize_narration.py` | Проверка длительности, выбор последних take-файлов и сборка дикторского stem |
| `narration-timeline.reference.json` | Измеренный таймлайн изготовленной версии; медиа передаются отдельно |
| `radio-provenance.reference.json` | Происхождение исходного радио, точный отрезок и машинные временные метки |

## Повторная генерация

Нужны Python 3.10+, `ffmpeg`, `ffprobe` и доступный аккаунт ElevenLabs. Дополнительные Python-библиотеки не требуются. Передайте API-ключ через переменную окружения **`ELEVENLABS_API_KEY`**, используя свой менеджер секретов. Скрипт не принимает ключ аргументом командной строки, не выводит тело ошибок провайдера и не содержит привязки к конкретному хранилищу.

Из корня репозитория задайте каталог **вне Git** и запустите первую группу:

```sh
export FIREWATCH_VIDEO_DIR="$HOME/firewatch-video-s6"
python3 dashboard/video/s6/generate_narration.py \
  --output-dir "$FIREWATCH_VIDEO_DIR" \
  --beats B01 B02 B03 B04 B05 D01
```

Каждый запуск `generate_narration.py` с ключом выполняет платные запросы. Без `--beats` генерация не начинается. Остальные группы:

```sh
python3 dashboard/video/s6/generate_narration.py --output-dir "$FIREWATCH_VIDEO_DIR" --beats D02 D03 D04 D05 D06 D07
python3 dashboard/video/s6/generate_narration.py --output-dir "$FIREWATCH_VIDEO_DIR" --beats D08 D09 D10 D12 D13 T01
python3 dashboard/video/s6/generate_narration.py --output-dir "$FIREWATCH_VIDEO_DIR" --beats T02 T03 F01 F02 F03
```

**D11 не генерируется:** весь блок 74–78 секунд свободен от диктора. Между запросами сохраняется `voice/voice.lock`. Готовые файлы не перезаписываются; не более трёх take-файлов на реплику. Если реплика длиннее окна, измените её текст в копии плана, передайте `--plan` и повторите только этот beat. Не применяйте `atempo`, обрезку слов или ускорение для подгонки. Перед третьей попыткой обязательно измените неудачную формулировку.

После получения всех реплик:

```sh
python3 dashboard/video/s6/finalize_narration.py --output-dir "$FIREWATCH_VIDEO_DIR"
```

Получатся `voice/final/<beat>.wav`, `voice/narration-120s.wav` и новый `production/narration-timeline.json`. Финализатор проверяет границы окон, отсутствие пауз от 0.8 секунды, плотность речи и безопасную границу удаления хвостовой тишины. При неудачном take он останавливается; это не основание считать близкий к окну файл готовым. Финальный файл блокирует повторную генерацию соответствующей реплики в том же каталоге: новую версию следует делать в другом каталоге.

## Исходное радио

В D11 используется **оригинальный трёхсекундный фрагмент**, не TTS: Palisades Command / Los Angeles County Fire V-1, 7 января 2025, публикация [Broadcastify](https://www.broadcastify.com/events/2025-01-lafire/). Атрибуция в кадре — **Audio Provided by Broadcastify**; лицензия по исходной публикации и сохранённому манифесту — [CC BY 3.0 US](https://creativecommons.org/licenses/by/3.0/us/).

Отрезок начинается на **138.25 секунде** `decision-focus.wav`, что соответствует **430.25 секунде** полного десятиминутного файла. Его длительность — 3 секунды, положение в монтаже — **74.5–77.5**. Хэш, исходный архивный файл, сдвиг `focus + 292 = full`, segment IDs и временные метки слов сохранены в `radio-provenance.reference.json`. Медиафайл необходимо получить отдельно из исходного пакета `palisades-radio-demo`; Git-пакет не содержит его копии.

Радио относится к **другому реальному инциденту** и не подтверждает условия синтетического Base2. Во время воспроизведения обязательна подпись **Palisades archive · separate incident**. Не заменять исходную реплику синтезированной «чистой» версией.

## Монтаж и границы утверждений

- В начале демонстрации: **Training replay · Base2** и **Synthetic site data · separate archived radio**.
- При скачке между моментами симуляции: **Replay excerpt**. Сохранить видимые часы replay; монтажная склейка не должна изображать непрерывное реальное время или задержку модели.
- D04 — фактическая автоматическая оценка новых данных. Самостоятельный выбор дополнительных источников или инструментов этим роликом не заявляется.
- T01 — агент читает полученные данные с источником и временем. **World Model / Active Sensing — Design goals**, а не полностью реализованные механизмы.
- D13 опирается на записанную потерю питания датчиков Gradas. Конкретные значения остаются в реальном интерфейсе; последнее измерение не становится текущим после потери связи.
- Метаданные камеры и доступность видео не означают, что LLM просмотрела кадры. Не объявлять визуальное распознавание по одному показу видео в интерфейсе.
- Разрешение доступа не доказывает проход или текущее присутствие. Неизвестное число людей не равно нулю; пустой кадр не доказывает эвакуацию.
- Историческая карточка Chevron показывает температуру **трубы**, а не воздуха: часть пожарных полагала около 130°F, фактическая — около 640°F. Ссылка и контекст находятся в S6; это не результат работы нашего продукта.
- Цель пилота — 30% быстрее получать корректный ответ без роста ошибок. Использовать **Not yet measured**: это не измеренный эффект и не существующий клиент.

## Субтитры и ограничения ASR

Субтитры строятся по **фактическим финальным WAV**, затем временные метки сдвигаются на `start_s`. Начальная тишина уже находится в файле; дополнительный сдвиг не нужен. Для сокращённых хвостов использовать именно `voice/final`, а не оригинальные MP3. Провайдерские character alignment сохранены для проверки, но не заменяют проверку распознанных слов.

Для радио сохранён исходный word clock Whisper `large-v3-turbo-q4`; соответствие выбранному PCM-фрагменту проверено. Отдельная проверка Whisper small на **20 секундах исходного контекста** распознала ту же фразу. Это машинная перекрёстная проверка, не измеренный WER и не эталонная ручная расшифровка. Короткий радиоотрезок, тишина и позывные могут давать пропуски или выдуманные слова: не восстанавливать неразборчивую речь по ожидаемому тексту и не оценивать точность по внутренней confidence модели.

В production-пакет не включены инструменты прожига субтитров, шрифты и другие bundled-исходники сторонних плагинов. В изготовленном MP4 проверены декодирование, длительность, аудио, наличие всех 58 субтитров сравнением пикселей и визуальные кадры каждого монтажного блока. ASR сверял фактические WAV; это не полный ручной аудит произношения носителем языка.

API: [Create speech with timing](https://elevenlabs.io/docs/api-reference/text-to-speech/convert-with-timestamps), [List voices](https://elevenlabs.io/docs/api-reference/voices/search). Голос и модель были проверены через API перед изготовлением этой версии.

## Сборка изображения и звука

`assemble.py --root "$FIREWATCH_VIDEO_DIR"` собирает 120-секундный clean MP4. Нужны внешний набор медиа и `ffmpeg`/`ffprobe`; в текущем скрипте используются системные шрифты macOS Arial и Arial Bold. `edit.reference.json` фиксирует все планы и обрезки. Скрипт читает `slides/slides.json`, PNG слайдов, `capture/<scene>/frames.json` и соответствующие PNG, `voice/narration-120s.wav`, `production/radio-original-3s.wav`. Выход: `firewatch-120s-clean.mp4`.

Запись интерфейса сделана штатными снимками вкладки браузера приблизительно с частотой 5 кадров/с. Из ответа screenshot удалён дублированный тайл; сохранены исходные PNG и фактические интервалы между кадрами. Выходные 30 fps повторяют кадры записи, не создавая новой информации. Переходы между моментами сценария помечены `Replay excerpt`; это смонтированная демонстрация, не измерение задержки модели. Крупные планы — обрезки реального интерфейса, ответы не дорисованы. Небольшой текст в исходной записи мягкий при увеличении; заголовки и субтитры рендерятся в 1080p.

`captions.reference.srt` содержит английские реплики данной версии. Их нужно прожечь в clean master через инструменты субтитров, затем проверить полученный файл; clean master хранится отдельно. Сторонние bundled-инструменты и шрифты не распространяются в репозитории.

## Исправленная версия Sharp

После замечания о размытии все планы интерфейса 25–90 с перезаписаны через Chrome в полном CSS-разрешении, без уменьшенных тайлов первоначального захвата. Крупные планы берутся из более чётких оригиналов. `assemble_sharp.py --root "$FIREWATCH_SHARP_DIR" --approved-video "$FIREWATCH_APPROVED_VIDEO"` использует эти новые кадры и копирует утверждённую AAC-дорожку исходного фильма без перекодирования. План — `edit.sharp.reference.json`. Кодирование изображения: CRF14 для clean и CRF16 при прожиге тех же 58 субтитров; faststart добавлен без перекодирования. Файл видео и слайды передаются отдельно от Git.

Повторная запись использует тот же G5 и реальные сохранённые ответы. В обзорном плане исходный run продолжен и достиг своего нормального конца 03:26. Статичные панели удерживаются до конца монтажного окна; аудио, сценарий и общая длительность не изменены.
