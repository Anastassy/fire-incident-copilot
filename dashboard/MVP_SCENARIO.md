# MVP-сценарий: собрать картину Base2 из всех источников

**Главный вопрос оператора:** «Что сейчас известно о Sala de Gradas, какие данные потеряли актуальность и можем ли мы подтвердить присутствие людей?»

**Основа:** существующий `base2-palisades-v1`, 206 секунд; Firewatch в `dashboard/live/`. Это учебный составной replay, не реконструкция пожара Palisades или Chevron. Многоканальность обязательна по решению пользователя. План ниже конкретен по действиям и основаниям; точные event IDs и срез с потерей связи нужно выбрать из фактического прогона перед записью.

## Одной схемой

Камеры + температура + дым + питание/связь + доступ + радио
↓
Оператор открывает Base2 и запускает replay
↓
Меняются показания; часть сведений перестаёт обновляться
↓
Copilot сам проверяет: что изменилось, какие источники ещё актуальны
↓
Одна карточка связывает измерения, состояние источников и доступный видеоинтервал
↓
Оператор: «Можем подтвердить, что внутри есть люди?»
↓
Copilot проверяет доступ, occupancy, видеооснования и происхождение радио
↓
«Запись доступа не доказывает присутствие; подтверждённого счётчика нет. Радио Palisades относится к другому инциденту»
↓
Оператор открывает основания и докладывает: что наблюдается, где потеряна актуальность, что требует уточнения

## Зачем нужен каждый источник

| Источник в текущем UI | Конкретная роль в сцене | Граница вывода |
|---|---|---|
| TMP-B2-GRADAS, TMP-B2-GALLERY, TMP-B2-COWORK | Показать измерения выбранной и соседних зон; изменение относительно прежнего значения | Число само по себе не доказывает пожар; зоны не смешивать |
| SMK-B2-* | Сопоставить дымовые измерения со временем и доступностью источника | Старое/нулевое/отсутствующее значение различимы |
| PWR-B2-GRADAS и connectivity | Проверить, почему наблюдаемость могла ухудшиться | Совпадение не доказывает причинность; не объявлять здание обесточенным |
| CAM-B2-GRADAS и CAM-B2-GALLERY | Открыть опубликованный кадр/фрагмент и сопоставить его время с показаниями | Между окнами нет нового видео; старый кадр не опровергает новые данные. Семантическое содержание требует просмотра/анализа, не угадывается |
| ACCESS-B2-GRADAS | Проверить, что зарегистрировал контроль доступа | Разрешение доступа не равно проходу; проход не равен текущему присутствию |
| Occupancy | Явно показать отсутствие подтверждённого числа людей | В этом наборе нет прямого источника; null не превращается в 0 |
| RADIO-B2-PALISADES + транскрипция | Показать и прослушать реальный радиоисточник, проверить его содержание и пригодность как основания | Архив относится к другому инциденту. Отказ использовать его как доказательство Base2 — часть проверки источников |
| Происхождение, время, схема зон | Связать только подходящие наблюдения и объяснить исключения | Общий run не означает общие место и историческое событие |

Все типы источников участвуют в проверке, но не все обязаны подтверждать одну гипотезу. Отсутствие/непригодность источника — значимый результат, а не повод его спрятать. Все устройства доступны в журнале; за 65 секунд не требуется отдельно открывать каждый датчик.

## Основной показ — 65 секунд

Внешние секунды показа не равны времени State run. Для репетиции выбрать уже опубликованный срез/поставить на паузу; на экране остаются реальные часы сценария. Seek меняет generation, поэтому контекст агента необходимо согласовать заново. Монтировать как учебный разбор, не подменяя скорость системы.

| Секунды основного показа | Действие и видимый результат |
|---|---|
| 0–8 | Обзор двух камер, датчиков, доступа, радио и состояния людей; явно «synthetic Base2 + archived Palisades» |
| 8–22 | Replay показывает изменение данных/доступности; фоновая проверка запрашивает историю и обновляет одну карточку по нескольким источникам |
| 22–34 | Оператор открывает измерение и соответствующий видеофрагмент; видно время каждого. Сохранённый кадр не выдаётся за непрерывное наблюдение |
| 34–49 | Вопрос о присутствии людей: access, occupancy, камера и радио проверяются; ответ отделяет наблюдение от предположения |
| 49–57 | Один короткий аудиоинтервал, проверка происхождения: Palisades не подтверждает обстановку Base2 |
| 57–65 | Оператор докладывает руководителю только подтверждённые изменения и пробелы. Реплика — ролевая сцена, не передача в историческую запись |

Общее видео: 0–15 проблема, 15–25 подход, 25–90 этот показ, 90–105 действительная архитектура/вызовы, 105–120 измерение или следующий шаг пилота. Новые 25 секунд вступления объясняют весь продукт. Старый сценарий только про V-Fire 25 не является заменой этого плана.

## Ожидаемый ответ, а не зашитая реплика

«Последняя температура в Gradas — [значение, время, источник]. Дымовое наблюдение — [значение/отсутствие, время]. По [событие связи/питания] актуальность [конкретного источника] ограничена. Последний доступный кадр — [время]. Запись доступа содержит [реальный тип события]; подтверждённого числа людей нет. Радиозапись относится к Palisades и не подтверждает присутствие в Base2».

Поля заполняются только фактическими результатами запросов. Не подставлять старые 42.2 °C из room-fixture, 54/338 °C из Chevron или выдуманный доклад «видимость ухудшается». Визуальный анализ кадра возможен только при действительном вызове соответствующего инструмента/модели; иначе оператор просматривает его сам, а агент сообщает время и доступность.

## Что уже есть и что требуется до показа

**Есть по текущему коду и отчёту live/VALIDATION:** два CCTV, радио, показания/статусы, история и evidence viewer, API вопросов и карточек. В отчёте зафиксирован полный run: 811 наблюдений и 43 транскрипции. Это объём одного проверенного прогона, не гарантированная пропускная способность.

**Не готово как подтверждённый общий результат:** связать реальный State run с импортом платформы и agent context; проверить семантический многоканальный ответ/фоновую карточку; решить доступ к media evidence агента. Тестовые Demo request/Assign/Reply идут в отдельную синтетическую сессию — они не анализируют Base2.

Перед записью необходимо:

1. Получить snapshot/history конкретного Base2 run и составить cue sheet: run/scenario version, generation, device/evidence IDs, значения, время и ожидаемый вывод для каждого шага. Точное окно потери актуальности пока не установлено этим аудитом. Документированные окна CCTV: [0,15), [68,83), [128,143), [176,191) секунд.
2. Зафиксировать device scope агента и преобразование State evidence → platform reading_id. Не выдумывать ID; ts=received_at в mapper не является временем seek.
3. Реализовать/проверить многоканальную фоновую проверку; наличие channel reducer не закрывает этот пункт. Приложить реальные queries и coverage.
4. Прогнать негативные случаи: нет occupancy, пропуск разрешён без passage, камера устарела, датчик отключён, радио другого инцидента, ошибка запроса, reset. Неизвестность не превращается в безопасность.
5. Если эти пункты не закрыты, показать честно интерфейс потоков и неподключённый/fixture агент; не называть это завершённым MVP и не откатывать описание продукта к одному радио.

## Связь с реальным примером

Внешнее обоснование — информационные расхождения в Chevron Richmond и другие случаи Evidence Bank. Учебный пример — Base2. Реальный материал — радио Palisades. Это три разные роли, а не три названия одного происшествия. Чтобы радио причинно подтверждало события Base2, нужен отдельно подготовленный и помеченный учебный радиопоток; его создание/подключение сейчас не подтверждено и не является скрытой предпосылкой этого сценария.
