# Контракты интеграции

## Актуальная версия State Machine

Использовать [State Machine 0.2.2](fire-safety-state-api-v0.2.2/README.md): [подключение](fire-safety-state-api-v0.2.2/v0.2/CONNECTION.md), [Palisades replay](fire-safety-state-api-v0.2.2/v0.2/PALISADES.md), [OpenAPI](fire-safety-state-api-v0.2.2/v0.2/openapi.json). Схема остаётся 0.2. Добавлены непрерывные fMP4-потоки и готовые radio_transcript; серверный ASR не выполняется. Работа сервера заявлена поставщиком, нами в этой задаче не проверена.

Старый пакет v0.2 — исторический 0.2.0-draft; его описание отсутствующего сервера и отсутствующих транскрипций больше не определяет актуальную интеграцию. Оба пакета сохранены без изменений. Safety Telemetry Platform v1 — отдельный сервис; требуется адаптер.

Это разные границы интеграции. v1 не заменяет v0.2: требуется адаптер; run/generation/cursor и Bearer первого пакета отсутствуют во втором. Подробное сопоставление и нерешённые вопросы находятся в PROJECT_CONTEXT.md в корне проекта.

## Safety Telemetry Platform v1

Начать с [CLIENT_FLOW](safety-telemetry-platform-v1/CLIENT_FLOW.md), затем [OpenAPI](safety-telemetry-platform-v1/openapi.json), [MCP tools](safety-telemetry-platform-v1/mcp-tools.json) и [примеров](safety-telemetry-platform-v1/examples/). Пакет перенесён без изменения содержимого.

Для UI: REST — полное состояние, SSE — live-обновления без replay; после обрыва нужна повторная REST-синхронизация. Для evidence требуется detail incident. SSE телеметрии не содержит reading ID. Для агента: MCP поддерживает чтение и запись, но обязательная severity при создании incident конфликтует с нашими границами и требует согласования. API вопрос/ответ, привязка источников к отдельным утверждениям, схема фоновых карточек и доставка медиа пока не определены полностью.

### Связь с нашим интерфейсом

- Сырые события, измерения и ссылки на медиа доступны по этому контракту; snapshot содержит последнее состояние, observations — историю, evidence — исходную запись.
- Ответы со ссылками на утверждения и обновляемые фоновые карточки относятся к внешнему агентному слою. Их API в пакете отсутствует.
- Связывать выводы и доказательства через run_id, generation, evidence_id и media_id. Результаты распознавания хранятся отдельно от исходных данных.
- Не отождествлять весь концептуальный Data Platform / World Model с этим ограниченным контрактом State Machine. Способ подключения State Machine к Data Platform и владельцы адаптеров требуют согласования.
- Упоминание анализа опасности во внешнем проекте не отменяет наши ограничения: агент не назначает HIGH / MEDIUM / LOW и не даёт тактических указаний.

### Следующий шаг интеграции

Можно строить локальный адаптер по snapshot.initial.json → events.json → snapshot.after-play.json и отдельно подключать тестовые медиа. До сетевой интеграции нужны рабочий base URL, application token, CORS origin и scenario_id. Для карточек и ответов нужен отдельный согласованный контракт агента.
