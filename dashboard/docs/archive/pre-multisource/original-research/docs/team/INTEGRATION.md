# Карта подключения команды

Это стартовая карта по уже зафиксированному scope, не новый API и не назначение дополнительных исполнителей.

| Участок | Зафиксированный владелец | Первый результат для объединения |
| --- | --- | --- |
| UI | Настя | Перенести согласованный Palisades-экран в выбранный стек; источник/время, полный журнал, evidence viewer и два вопроса |
| Источник/replay | Виталий И. | `palisades-focus`, общий run/generation, публикация ASR только после завершения фразы, доступ к аудио |
| Data Platform | Виталий Н. | Доступ и ingest/read по v1, устойчивые reading_id, сохранение provenance |
| Адаптер | Требует назначения | Пример радио observation → telemetry, соответствие ID и изоляция прогонов |
| Два режима агента | Требует назначения | Фоновая проверка одной карточки + ответы на два вопроса реальными read-only запросами |
| Agent→UI и media resolver | Требует назначения | Согласованный метод вопроса/обновления карточки и переход reading → исходный аудиоинтервал |

Артём — получатель scope; исполнительская роль пока не зафиксирована. До реализации обменяться в PR именем владельца, входом/выходом, примером payload, командой запуска и способом проверки участка. Раскладку кода UI/агента в каталоги определить вместе с выбором стека; пустые сервисы здесь не создаются.

## Стык сервисов

Путь: State Machine 0.2.2 → адаптер → Safety Telemetry Platform v1 → UI/read-only MCP агента → производные claims/карточка → исходные данные. Контракты доступны через [навигатор](../contracts/README.md). Сеть и готовность интеграции этим экспортом не проверяются.

Для адаптера предложены `metric_type=other`, `payload.kind=radio_transcript`; это ещё не реализованная договорённость. Сохранить run/generation, source ID, media ID, таймкоды, derived/machine_generated/human_verified, исходное время и время доставки. В платформе нет серверного run-фильтра: нужен namespace внешних device ID на прогон и ограничение выборки согласованными UUID.

SSE платформы не содержит reading.id и не поддерживает replay. После обрыва перечитывать REST; доказательства связывать с настоящим integer reading_id, не с выдуманным ID или временным URL. Общий ключ платформы хранить за серверным прокси. Гипотезы не создавать через incident с обязательной severity.

Черновая структура agent→UI уже описана в [03_DELIVERY](../../team-handoff/mvp-scope/03_DELIVERY.md): контекст, as_of, claims/evidence, unknowns, queries; устойчивая карточка с revision. Endpoint и доставка обновлений ещё не согласованы. В полном JSON ASR есть будущее: держать файл на стороне replay/подготовки, не давать агенту целиком.

## Первый сквозной прогон

1. Общий paused run и история до 02:10.420 focus; запрос есть, назначения/подтверждения в доступном срезе ещё нет.
2. Play 1×; публикация назначения и подтверждающей реплики обновляет одну карточку.
3. Вопрос о канале даёт два отдельных основания; обе ссылки открывают нужное аудио.
4. Вопрос о переходе всей группы оставляет выполнение неизвестным.
5. Повтор без подтверждающей реплики меняет результат; reset отменяет старые ответы и аудио. Ошибка запроса остаётся ошибкой, а не доказательством отсутствия реплики.

Таймкоды предварительные, по непроверенному ASR. Ручное прослушивание обязательно до финального показа. Это критерии будущей интеграции, не пройденный тест пакета.
