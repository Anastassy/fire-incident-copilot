# Palisades: интерфейс и сценарий взаимодействия

## Актуально: V3 — сценарий во времени

Главный вопрос экрана — **Did the group get an answer?** Название V-Fire 25 находится в пояснении найденного ответа. V3 заменяет компоновку и поведение V1/V2 ниже: одна крупная карточка, последняя реплика, раскрываемые журнал и вопросы, видимые Start / pause / Restart.

После запуска из 02:10.420 последовательно появляются назначение (02:15.760) и подтверждающая реплика (02:20.260). На каждое новое сообщение есть отдельное состояние проверки Copilot. Результаты: «ответ пока не найден» → «ответ найден» → «подтверждающая реплика найдена». Доказательства и доступная история растут по виртуальному времени. Кнопка Listen открывает точный аудиоинтервал и ставит replay на паузу. Вопрос о переходе всех участников демонстрирует предел доказательств; черновик доклада предназначен оператору.

Это интерактивный мок с реальным архивным аудио, без подключённой модели/Data Platform. Фоновые проверки и ответы симулированы и помечены. Data, replay, agent, media выделены в заменяемые адаптеры; описание подключения, контрольных веток и сценарий **65 секунд** основного показа: [README](docs/design/palisades/README.md). Код: [макет](docs/design/palisades-console.html). Полное видео — 120 секунд, основная демонстрация 25–90; вводная не раскрывает ответ.


## Редизайн V2 — актуальная компоновка после исследования

Пользователь оценил предыдущий экран как сложный с первого взгляда. Проведены [исследование критичных HMI](docs/research/CRITICAL_INTERFACE_RESEARCH.md) и [проверка официальной рубрики хакатона](docs/research/HACKATHON_CRITERIA_RESEARCH.md). Эта секция заменяет компоновку двух равных зон, описанную ниже; функциональные границы и происхождение остаются прежними.

**Теперь на первом экране один результат:** крупно `V-Fire 25`, ниже `Reply found in transcript`, справа единственное основное действие `Listen to reply`. Граница вывода про неподтверждённый переход всех участников остаётся видимой. Две ссылки на назначение и ответ находятся в нижней строке карточки. Одна последняя реплика — под карточкой. Полный опубликованный журнал с поиском открывается постоянной кнопкой со счётчиком; Ask Copilot раскрывается только по запросу. Трёхшаговый чеклист и постоянно открытые вопросы убраны с обзора.

Управление ведущего свёрнуто. В макете есть три подготовленных среза, примерно 10-секундное воспроизведение от 130.420 до 140.260 с и состояние ошибки проверки. В рабочем приложении переходы обязаны зависеть от фактических запросов, а не таймкодов сценария. Макет не реализует модель/платформу.

Официально подтверждены: четыре критерия 1–5 (работоспособность, тема/новизна, техническая интеграция, полезность/агентский опыт), двухминутное видео. Процентные веса не опубликованы. План видео: 25 с вступления + 90 с основного показа + 5 с завершения. Надёжный реальный контур агента важнее дополнительных украшений; один макет не закрывает критерии интеграции.

Предыдущий HTML сохранён как [V1](docs/design/palisades-console-v1.html) для сравнения. [Актуальный макет V2](docs/design/palisades-console.html).

12 сентября 2026. Пользователь прямо подтвердил scope: Palisades — основной кейс. Эта спецификация определяет актуальный экран и заменяет комнатную компоновку для основного демо.

**Результат:** один desktop-экран сотрудника поддержки командования. Слева — доступные записи радио, справа — Copilot, который проверяет связь «запрос → назначение → подтверждающая реплика». Оператор открывает основания и формулирует короткое сообщение руководителю. Наиболее заметное действие агента — самостоятельное обновление результата после поступления новой записи.

[Кликабельный макет](docs/design/palisades-console.html). Это дизайн-прототип с подготовленными состояниями, настоящим локальным аудио и исходным ASR. Он не подключён к платформе/модели; кнопки ведущего не являются демонстрацией работающего агента. Полный текст встроен только для удобства просмотра макета офлайн; в рабочей системе агент получает исключительно опубликованную историю.

## 1. Что предполагаем у оператора до нашего продукта

Рабочая гипотеза: у сотрудника информационной поддержки есть канал радио, возможность прослушивать сообщения и журнал/заметки для подготовки сведений руководителю. Точная историческая консоль участников Palisades по нашим материалам не установлена. Мы не реконструируем её и не заявляем, что этих людей обслуживала конкретная CAD-система.

Для честного сравнения **наш базовый интерфейс** даёт радиоархив, машинный текст, время, поиск и воспроизведение. Это выбранный baseline эксперимента, а не утверждение, что готовая транскрипция была у оператора 7 января 2025. Не ухудшаем baseline намеренно: ручной поиск и те же источники доступны без Copilot.

| Блок | Базовая функция | Что добавляет Copilot |
|---|---|---|
| Радиоканал, аудио | Прослушать опубликованную запись | Найти интервал, подтверждающий конкретный ответ |
| Текст и время | Прочитать/найти реплику вручную | Связать разнесённые реплики по вопросу оператора |
| Журнал | Просмотреть всю доступную историю | Предложить проверку и объяснить её результат, сохранив полный доступ |
| Заметка руководителю | Оператор формулирует самостоятельно | Короткий проверяемый черновик из найденных оснований |
| Связь с командой | Существующая рация/голосовое общение | Автоматической передачи нет; человек использует проверенные сведения |

Наш продукт демонстрирует поддержку понимания радиообмена. Он не показывает ориентирование внутри зданий, позиции людей или состояние их радиостанций. Промышленные оперативные центры остаются гипотезой первого рынка, Palisades — реальный материал проверки функции.

## 2. Пользователь и решение

**Пользователь:** сотрудник поддержки командования, находящийся рядом с руководителем или на рабочем месте штаба. Это наша демонстрационная роль; мы не отождествляем её с неизвестным говорящим в записи.

**Задача:** на вопрос руководителя «Какой канал назначили Coastline и есть ли ответ?» быстро найти запись назначения и отдельную подтверждающую реплику.

**Решение пользователя:** что он может сообщить руководителю с основаниями и что остаётся неустановленным. Он не утверждает состояние всех людей/радиостанций по одной реплике. Тактические решения остаются вне приложения.

## 3. Компоновка: две зоны вместо трёх колонок и длинного чата

Целевой экран — 1440×900, desktop, английский язык. Цвета: спокойный сине-серый фон `#EFF3F6`, тёмный текст `#1D3040`, белые источники, синий акцент Copilot `#185C85`, светло-синий фон результата `#E7F2FA`. Состояния обозначены словами; цвет не означает уровень опасности. Заголовки Avenir Next/системный fallback; время — моноширинное.

```text
Palisades / Radio desk                       Recorded replay · 02:20
┌───────────────────────────┬──────────────────────────────────────┐
│ RADIO LOG                 │ COPILOT · background check           │
│ Palisades Command · V-1   │ Coastline / Channel assignment       │
│                           │                                      │
│ 02:08 запрос          ▶   │ Запрос → Назначение → Реплика        │
│ 02:13 назначение      ▶   │   ▶          ▶          ▶            │
│ 02:18 ответ           ▶   │                                      │
│                           │ V-Fire 25 · reply found               │
│ Все опубликованные фразы │ [Was it acknowledged?] [Follow-up]   │
└───────────────────────────┴──────────────────────────────────────┘
                 Доказательство открывается по клику
```

### Верхняя строка

Инцидент, дата, `Recorded replay`, позиция записи. В рабочем варианте — отдельный маленький статус соединения. Название доступного канала не путать с назначенным в разговоре V-Fire 25: **мы слушаем архив V-1, а не подключаемся к V-Fire 25**.

### Левая зона: источники, около половины ширины

Один доступный радиоканал. По умолчанию три последние опубликованные фразы, хронологически, каждая с временем и кнопкой прослушивания. Счётчик `Latest 3 of 27 published phrases` объясняет сокращённый вид. `All published phrases` открывает полный журнал с поиском в рабочем приложении. Никакого агентного отбора «важности».

Метка `Machine transcript · not human-verified` относится ко всем текстам. Имена говорящих и аватары не придумываем. Состояние «нет новых опубликованных фраз» не называется «команда не отвечает».

### Правая зона: агент

Одна фоновая карточка по теме Channel assignment. Три шага — это **стадии доказанности обмена в доступном тексте**, а не прогресс выполнения операции командой.

| Срез истории | Запрос | Назначение | Подтверждающая реплика | Короткий вывод |
|---|---|---|---|---|
| t=130.420 с | Есть в тексте | Пока не найдено | Пока не найдено | Assignment not found in the available transcript |
| t=135.760 с | Есть | V-Fire 25 | Пока не найдено | V-Fire 25 assigned. Reply not found yet |
| t=140.260 с | Есть | V-Fire 25 | Найдена в тексте | V-Fire 25 · acknowledging reply found |

Шаги открывают свои отдельные источники. Назначение — 133.260–135.760, подтверждающая реплика — 138.700–140.260 секунд короткого файла. Эти границы и содержание пока взяты из ASR; запуск плеера при проверке макета не равен ручной проверке точности речи.

Ниже карточки — кнопка основного вопроса `Was it acknowledged?`, уточнение `Did everyone switch?` и поле свободного вопроса. В рабочем приложении любые формулировки обрабатываются реальным агентом в выбранном контексте; две кнопки только сокращают ввод. В макете свободный ввод честно сообщает, что модель не подключена.

Ответ появляется только после вопроса и занимает 1–2 предложения, обычно до 35 английских слов. Ссылки стоят рядом с соответствующими утверждениями. Если ответ содержит два отдельных утверждения — две самостоятельные ссылки, а не общий список в конце страницы. Длинные детали находятся за `Evidence / Check details`.

### Просмотр доказательства

Открывается только по действию пользователя: короткая реплика, проигрывание ограниченного интервала, время, происхождение. Технические поля раскрываются отдельно. Закрытие останавливает аудио и возвращает фокус. Само открытие не помечает смысл вручную проверенным.

Целевой вариант для desktop — боковая панель/выдвижная область, сохраняющая карточку в поле зрения. В кликабельном макете использован стандартный dialog для проверки взаимодействия и клавиатуры; это упрощение макета, не обязательная реализация панели.

При прослушивании доказательства второй аудиопоток приглушается/останавливается локально, а поступление событий продолжается. После закрытия виден счётчик новых сообщений. В записанной презентации ведущий может поставить replay на паузу; эта возможность не переносится на реальную команду и живой эфир.

### Ограничение текста

- На стартовом экране: три короткие реплики, одна агентная карточка и одна строка результата.
- Один активный ответ; предыдущие ответы доступны в раскрываемой истории, не растягивают весь экран.
- Один обновляемый объект проверки; не создаём новую карточку для каждой реплики.
- В рабочей зоне нет бизнес-обоснования, архитектуры, JSON, цепочки рассуждений модели и длинных объяснений о безопасности.
- Сеть/ASR/неполнота подписаны компактно; подробности доступны по клику.
- В более длинной работе другие проверки доступны через список/счётчик, без автоматического скрытия исходных событий.

## 4. Где видна ценность двух режимов агента

**Фоновый режим:** получает новое опубликованное наблюдение, формулирует проверку наличия назначения/подтверждения, читает соответствующую историю и обновляет карточку. Оператор не должен сначала нажать Ask. На время инструмента показываем `Checking available history…`, при неудаче `Check unavailable`, а не «ответа нет».

**Режим вопроса:** переводит запрос человека в поиск по текущему обмену; на первый вопрос находит две реплики, на второй проверяет, есть ли основания утверждать переход всех участников. Ответ второго режима не равен повтору заголовка фоновой карточки.

UI не показывает двух аватаров или спор двух ботов. Это два способа работы Copilot. Статусы технической проверки — проверяется/поддержана/опровергнута/недостаточно данных — доступны в деталях. Три визуальных шага обмена не заменяют эти статусы.

**Запоминающийся момент:** в эфире слышно короткое подтверждение, карточка обновляется, оператор одним нажатием открывает именно эту реплику. Затем агент различает «есть подтверждающая реплика» и «вся группа точно переключилась».

## 5. Оператор ↔ интерфейс ↔ команда

Основной сценарий — поддержка руководителя, а не новый диспетчерский центр управления всеми группами.

```text
Архив радио → опубликованные записи платформы → Copilot
                                             ↓
Руководитель задаёт вопрос → оператор → проверка и прослушивание
                                             ↓
Руководитель получает краткий доклад ← оператор
```

Два независимых источника звука/смысла:

1. **Историческая запись:** реальные реплики 7 января 2025; неизменяемая последовательность. Она не отвечает на клики или голоса участников демо.
2. **Ролевая сцена у рабочего места:** участники команды хакатона изображают оператора и руководителя; реплики ниже написаны для демонстрации, не взяты из Palisades. В видео пометка `Operator workflow reenactment`. Эти реплики не добавляются в архив как исторические доказательства.

| Кто | Реплика/действие в постановке | Основание |
|---|---|---|
| Руководитель | «Какой канал назначили Coastline? Есть ответ?» | Демонстрационный запрос пользователю, не историческая цитата |
| Оператор | Нажимает вопрос, открывает назначение и ответ | Два исходных аудиоинтервала |
| Оператор → руководитель | После собственной проверки аудио: «В записи назначен V-Fire 25; есть реплика с повторением канала. Переход всех участников этим не подтверждается» | Не сообщает больше, чем нашёл |
| Руководитель | «Понял. Основание есть» | Демонстрационное завершение информационной задачи |

Если оператор ещё не прослушал запись, формулировка другая: «По машинному тексту найдено назначение и ответ; проверяю аудио». Не показываем такую заметку как уже проверенный факт.

`Prepare briefing` открывает короткий черновик со временем и источниками. Оператор проверяет/редактирует его, копирует или говорит вслух. **Нет кнопки Send to team, PTT, автоматической радиопередачи или команды переключиться.** В MVP коммуникация с руководителем — вне системы; реальные внешние сообщения в рамках разработки не отправляются.

Если подтверждение не найдено, продукт показывает ограничение доступной записи. Решение уточнить по существующей связи принимает человек по своему процессу; агент не объявляет это универсальным регламентом и не запускает вызов самостоятельно.

## 6. Как показываем симуляцию

Один run `palisades-focus`, один доступный радиоисточник, 1× скорость. Часы файла — 206 секунд. Выделенный момент — 128.600–140.260. Полный и короткий файлы не являются независимыми свидетельствами.

**Подготовка ведущего:** прогнать опубликованную историю до 130.420 и поставить на паузу. Состояние агента построено из доступной истории, без будущего полного ASR и без редакционного сценария. Ведущий заранее проверяет интерфейс и audio resolver. Пауза сохраняет часы сценария; задержка запроса считается отдельно реальными часами.

| Время основного показа | Действие оператора/ведущего | Работа продукта | Что понимает зритель |
|---|---|---|---|
| 0–10 с | Ведущий обозначает архив; руководитель задаёт вопрос | Карточка фоновой проверки уже видна на срезе 02:10 | Есть конкретный человек и одна задача |
| 10–25 с | Ведущий продолжает replay в 1×; оператор наблюдает | Публикуются назначение и ответ; агент перечитывает историю и обновляет ту же карточку | Полезная проверка выполняется без клика Ask |
| 25–40 с | Оператор нажимает `Was it acknowledged?` | Реальный запрос с текущим контекстом; короткий ответ с основаниями | Агент помогает найти ответ, а не только выделяет событие |
| 40–60 с | Открывает и слушает назначение и подтверждение; диктор молчит | Плеер проигрывает соответствующие опубликованные интервалы | Основание слышно, его можно проверить |
| 60–75 с | Уточняет `Did everyone switch?` | Ответ отделяет реплику от состояния всех участников | Агент не превращает частичное свидетельство в лишний вывод |
| 75–90 с | Оператор готовит короткий доклад и произносит его руководителю | Черновик/источники доступны; отправки нет | Замыкается человеческий рабочий процесс |

90 секунд — монтажный ориентир, не SLA. Если запрос занимает дольше, реальный показ продолжается либо монтажный пропуск маркируется. Не показывать заранее записанный текст как выполненный вызов модели.

С [вступлением на 25 секунд](DEMO_OPENING_25S.md) это даёт около 115 секунд видео. Вступление показывает уже полученный результат; перед динамической частью явно обозначаем `Earlier in the replay · 02:10`. Для перезапуска/seek нужен новый generation с очищенными агентными ответами либо отдельный run. Иначе ранее увиденное подтверждение попадёт в «ещё не найдено» и демонстрация станет противоречивой.

В основной презентации нет D-Fire, карты пожара или виртуальных датчиков, выдаваемых за Palisades. Если эти тестовые потоки присутствуют на платформе, они доступны отдельно с происхождением; явный фильтр основного эпизода сохраняется.

## 7. Контрактные последствия и минимальный объём

Сохраняются решения [пересмотра](MVP_EVIDENCE_REASSESSMENT.md): нормализация `radio_transcript` через адаптер, реальные reading_id платформы, сохранение таймкодов/run/generation, media resolver для опубликованного интервала. UI не зашивает фразу V-Fire 25 как ответ действующего агента. Демонстрационный объект Coastline можно выбрать заранее как сценарный фокус; установление связей и утверждения о нём всё равно проверяются запросами.

Один UI-объект `exchange_check` содержит topic, scope, as_of, revision, request/assignment/reply с собственными evidence refs и состоянием проверки. Это производная интерпретация с основаниями, не новый источник фактов. Авторитетные сообщения остаются в платформе. Один вопрос передаёт exchange/scope, время среза и request_id. Черновик доклада связан с версией ответа; при новых данных помечается устаревшим.

Обязательны: журнал, поиск всей опубликованной истории, одна фоновая проверка, контекстный вопрос, два типа ответа, переход к аудио, короткий черновик доклада, обработка ошибки/переподключения/reset. Карточка с проверкой, которая не смогла прочитать источник, не получает состояние «подтверждено».

Не входят: отправка радио, распознавание живой речи, клонирование голосов, карты/позиции, расчёт воздуха, назначения ресурсов, 3D и автоматическая оценка риска.

## 8. Проверка готовности

1. До 135.760 назначение не раскрывается, до 140.260 не раскрывается подтверждающая реплика. Публикация идёт после завершения интервала, не по его началу.
2. Без Ask появляется проверка, связанная с опубликованными записями; в её деталях видны фактические запросы и время.
3. Ответы открывают правильные интервалы, а полная история остаётся доступной независимо от карточки.
4. Если убрать ответ из входа, Copilot не воспроизводит его из знания сценария. Если запрос к платформе упал, UI не трактует это как отсутствие ответа.
5. Повторные события не дублируют фразы. При reset нет старых ответов/аудио/черновиков.
6. Нет подтверждения личности говорящего или переключения всех участников без источника.
7. Клавиатурой доступны вопросы, источники и закрытие панели; аудио не запускается без действия. Нет двух одновременно звучащих дорожек.
8. На стартовом экране человек за несколько секунд различает исходные записи и результат Copilot. Проверяем на коллеге вопросами «Что сделал агент?» и «Где проверить это утверждение?»; результат пока не измерен.

### Статус макета

В браузере проверены переключение состояний и ограничение видимых фраз по срезу, открытие ответа и конкретного источника, запуск локального аудиоинтервала. Это проверка дизайна, не интеграционный тест Data Platform, не работа модели и не ручная верификация содержания ASR. Макет можно открыть как HTML из проекта; относительная ссылка на аудио требует сохранения структуры папок.
