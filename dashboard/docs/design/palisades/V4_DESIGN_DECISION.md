# V4: рабочий экран радиокоординации

V4 — предлагаемая и реализованная редакция дизайна после повторного исследования. Подтверждённый Palisades scope не меняется. Визуальная пригодность для реального оперативного использования ещё не проверена с пожарными.

## Одно предложение

Сотрудник поддержки командования видит исходный радиообмен и то, как Copilot связывает запрос, назначение и ответную реплику; затем проверяет оригинал и докладывает руководителю.

## Компоновка

```text
Fire Incident Copilot     Palisades / recorded radio     SIMULATED AGENT
Keep track of the reply.                           Start | Hide Copilot
┌ Источник · примерно 1/3 ┐  ┌ Copilot · примерно 2/3 ──────────────────┐
│ Incoming radio         │  │ Channel request              Check state │
│ V-1 · 5 последних      │  │ Текущий вывод + краткое пояснение         │
│ опубликованных реплик  │  │ Request → Assignment → Reply              │
│                        │  │ Каждое основание открывает аудио          │
│ Связанные выделены     │  │ «Все переключились?» — не установлено     │
│ Полный журнал / поиск  │  │ Следующий шаг оператора | Listen           │
└────────────────────────┘  │ Охват проверки | Ask Copilot              │
                            └───────────────────────────────────────────┘
Replay controls · часы focus · Restart · честное обозначение мока
```

Это не возврат к двум одинаково сложным панелям V1. Радио — компактный постоянный источник; основная область предназначена одной проверке. Значимая визуальная особенность — три связанных звена, которые появляются из потока. В интерфейсе не представлены отсутствующие карта, датчики или статусы людей.

## Визуальные решения

Палитра: командный синий #19394B для оболочки, текст #172D3B, фон #F0F3F4, действие #205E82, найденное основание #20645F, ожидание #7A520D. Цвета не задают severity инцидента. Явные надписи FOUND/NOT FOUND/Checking дублируют цвет.

Типографика: Avenir Next/Arial для чтения, Arial Narrow/Arial для компактного имени рабочего пространства, SFMono/Consolas для временных меток. Шрифты локальные, загрузки из внешней сети нет. Заголовок крупный, исходные записи компактнее, метаданные вторичны. Основная проектная ширина — desktop; при узком экране Copilot расположен перед источником. Для меньшей высоты предусмотрена прокрутка; кнопка запуска доступна и в шапке.

Не используются декоративные карты, красное аварийное оформление, псевдоосциллограммы, вымышленные показатели риска или счётчики спасённых людей. Изменение состояния заметно по заполнению цепочки и новому выводу. Анимация учитывает prefers-reduced-motion.

## Поведение во времени

Сохраняется реальный focus: 130.420 → 135.760 → 140.260 → 142 секунд. На старте ответа нет в опубликованном срезе. После назначения появляется второе звено. После ответной реплики — третье. Проверка происходит после публикации, с искусственной задержкой мока; это не метрика агента.

Во время повторной проверки остаётся последний вывод с меткой rechecking. Ошибка показывает last finding/check failed. Исходные сообщения остаются доступны. Каждый найденный шаг имеет свою кнопку Audio. Прослушивание ставит архивный replay на паузу и останавливается в конце интервала.

Hide Copilot убирает агентскую область и её выделение в радиоленте. Данные и время не меняются. Это объяснение добавленной функции, не измеренное преимущество. В демонстрации можно обойтись без этого переключения.

Ask why раскрывает вопрос о переходе всех участников. Ответ и черновик имеют время; при новых данных они помечаются как потенциально устаревшие. Restart закрывает доказательства и вопросы прежнего поколения. Копирование черновика не отправляет сообщение.

## Точки подключения

Сохраняются data/replay/agent/media. Новый renderer — workspace.js, стиль — workspace.css; V3 сохранён в palisades-console-v3.html и использует прежний app.js. Внутренний Check дополнен необязательным exchange: список {role: request|assignment|reply, evidenceId}. Роли определяет адаптер/агент, UI не извлекает их из текста и не классифицирует по времени. Без ролей нет выдуманных заполненных шагов. В текущем мок-режиме роли задаёт подготовленная фабрика.

При подключении /agent/v1 нельзя автоматически переводить supported в confirming reply found. Требуется явное сопоставление источников и стадии; assessment, lifecycle, publication_status и platform_status остаются отдельными понятиями. coverage и unknowns должны передаваться без потери. Внутренние короткие тексты V4 предназначены текущему сценарию; общие серверные карточки требуют адаптации, а не подстановки в поля наугад.

Мост платформы использует received_at как ts; интервалы симуляции хранятся в payload. Для проигрывания нужны именно media-relative start/end. Никакие API-ключи не добавлены. Полный live-контур этой редакцией не реализуется.
