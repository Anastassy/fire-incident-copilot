## 2. Основа вступления

**Пользователь:** сотрудник оперативной поддержки пожарного инцидента, который собирает информацию и готовит доклад руководителю. Промышленный оперативный центр с собственной пожарной службой — гипотеза первого рынка, не подтверждённый покупатель.

**Проблема:** камеры, датчики, радио, питание/связь и доступ обновляются неодновременно. Оператор вручную сопоставляет сведения, их время и пробелы, чтобы понять, что действительно подтверждено. Не утверждаем, что у него вообще нет мониторинга.

**Обещание продукта:** помочь собрать подтверждённую картину из разных источников и показать, что остаётся неизвестным. Это ценностное предложение; сокращение времени и эффективность пока не измерены.

**Основание:** текущие [контекст](PROJECT_CONTEXT.md), [Evidence Bank](EVIDENCE_BANK.md), [MVP](MVP_SCENARIO.md). Chevron — документированный пример информационного расхождения; Base2 — будущая учебная симуляция; Palisades — отдельный исторический радиоисточник. Эти материалы не изображают один пожар.

## 4. Доказательства и границы

**E1:** [CSB, Chevron Richmond Refinery Pipe Rupture and Fire, январь 2015, §5.3.2, печатная с. 93](https://www.csb.gov/assets/1/20/chevron_final_investigation_report_2015-01-28.pdf). Текущий Evidence Bank фиксирует: часть пожарных считала температуру линии близкой к 130°F, фактическая приближалась к 640°F. Округлённый перевод: 54°C и 338°C. Не два конкурирующих датчика; не температура Base2; не доказательство предотвращения аварии нашим продуктом. Источник повторно проверен в аудите банка; нового исследования для замены банка не требуется.

Возврат Chevron следует текущему банку, где он выбран основным доказательством. Прежний запрет из архивной radio-only вводной не переносится на актуальную многоканальную постановку. NIOSH остаётся дополнительным примером банка, но в эти 25 секунд не входит. Конкретные формулировки S5 — редакционное предложение для просмотра.

## 7. Кейс симуляции: «Картина изменилась. Что можно доложить?»

**Герой:** сотрудник оперативной поддержки пожарного командования. **Рабочая задача:** проверить состояние Sala de Gradas в учебном Base2 и подготовить доклад руководителю, включая ответ о присутствии людей. Промышленный оперативный центр — целевой контекст пилота; Base2 не объявляем действующим промышленным объектом.

**Завязка:** доступны камеры, температура/дым, питание/связь, доступ и радио. Затем измерения/доступность меняются; часть наблюдений больше не обновляется. Старый кадр и последнее показание продолжают существовать, но не дают актуального подтверждения. Запись доступа тоже не отвечает на вопрос «кто сейчас внутри?».

**Главный демонстрационный момент:** без предварительного вопроса оператору агент замечает изменение и недостаточность оснований, запрашивает дополнительную историю/источник и обновляет вывод. Затем вопрос человека меняет задачу проверки: от состояния помещения к подтверждению присутствия. Агент сопоставляет подходящие основания и оставляет присутствие неизвестным, если его нельзя подтвердить. Это проявление World Model и выбора следующей проверки; названия механизмов объясняем позднее.

**Развязка:** оператор может сообщить подтверждённые изменения, их основания и конкретный пробел. Руководитель получает обоснованный доклад; решений о входе, эвакуации или безопасности агент не принимает. Выигрыш, который показываем: разрозненные сообщения превращаются в проверяемое понимание. Ускорение этой работы — гипотеза для пилота, не уже полученная цифра.

**Данные:** существующий `base2-palisades-v1`, 206 секунд. Base2/CCTV/датчики синтетические; Palisades — архив другого инцидента. Все типы источников участвуют, но радио не является свидетельством о людях в Base2. Его короткий показ проверяет пригодность происхождения. Не строим весь сюжет вокруг отказа от чужого радио: этот момент занимает только 8 секунд из 65.

Это сценарная конкретизация [MVP_SCENARIO.md](MVP_SCENARIO.md), не задание переделать интерфейс или создать новые события симулятора. Расположение панелей, кнопки, дизайн и навигацию определяет параллельная работа над UI. Ниже описаны действия, смысл записи и результат, который должен быть различим.

## 10. Перед записью: фактические привязки, а не разработка интерфейса

Сценарий завершён как монтажный план. **Секунды фильма зафиксированы; event IDs, значения и время replay нельзя выдумать.** Они заполняются по одному выбранному прогону. Часы фильма и 206-секундного run различаются; монтажные переходы не должны выдавать сжатое ожидание за задержку агента. Не раскрывать будущие события модели.

| ID | Что фиксируем в записи/таблице привязок | Условие для основного сценария |
|---|---|---|
| G0 | run_id, scenario/version, generation, зона и device scope; исходный и изменившийся срезы | Везде одна согласованная сессия. Точный срез потери актуальности пока не выбран; не менять генератор для подгонки |
| G1 | Новое событие, реальные tool queries, возвращённые reading/evidence IDs, старая/новая версия вывода | Подтверждает самостоятельную многоканальную проверку для D04/D05/D07. FixtureEngine не подходит |
| G2 | Значения/время температуры и дыма, состояние питания/связи, опубликованный камерный интервал, доступный исходник | Доказательства для D03/D06/D07/D13; кадр просмотреть. Нельзя утверждать «камера видит дым» без просмотра/анализа. Известные окна CCTV [0,15), [68,83), [128,143), [176,191) не заменяют выбор фактического среза |
| G3 | Реальный вопрос, запросы access/occupancy/video/provenance и ответ с ограничениями | D09/D10/D12: permission ≠ passage ≠ current presence; чужой архив отвергнут по происхождению; missing ≠ zero |
| R1 | Аудиофайл, опубликованный интервал до 3 с, смещение focus/full, дословно проверенный субтитр, лицензия и атрибуция | D11: выбирается из доступного среза, не из будущего. Оригинал слышен без диктора. Неразборчивые слова не реконструировать |
| G4 | Реальная схема подключения, успешный end-to-end trace, коммиты вклада команды, используемые внешние SDK/модель/ASR | Основная реплика T03 только после сквозной проверки. На данный момент IMPLEMENTATION_STATUS подтверждает компоненты, но оставляет многоканальные разрывы |
| G5 | Метрика и условия пилота: 4–6 участников, два сопоставимых задания, чередование порядка; правильность/ошибки/неответы | 30% — только целевой ориентир. Начало отсчёта — достаточность данных для правильного ответа, не нажатие кнопки. Не называть малую UX-проверку доказанным промышленным эффектом |

**Если интеграция к записи не подтверждена:** сохранить честный показ источников, но пометить соответствующие сцены **Proposed agent workflow · integration pending**. Вместо D04 говорить **“The next integration step is automatic checks as new evidence arrives.”**, вместо D05 — **“The intended output separates supported observations from missing evidence.”**; D09/D10/D12 описывает оператор как ручную проверку с подписью **Operator-led verification**. Вместо T03: **“The replay interface and platform components are built. Multisource agent integration is the next validation step.”** Это демонстрация незавершённого прототипа, которая не доказывает агентские критерии. Готовые ответы нельзя озвучить как результат работающего агента. После такой замены проверить связанные реплики D07/D13 и титры на отсутствие утверждений об автоматическом выполнении.

**Репетиция:** без логинов/установки; один понятный эпизод; сохранить исходную непрерывную запись и реальные задержки. Проверить, что новый зритель после просмотра может назвать пользователя, проблему, одно действие агента, источник доказательства и неизвестное. Не добавлять отдельный crash-demo, TAM или все 11 архитектурных обязанностей ради полноты. Первый результат для записи — успешный воспроизводимый путь; запасной вариант — подписанная запись реального выполнения, а не анимация фиктивного ответа.
