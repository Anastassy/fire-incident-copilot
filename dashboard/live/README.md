# Firewatch — живой экран Incident Copilot

Copilot — главный блок: автоматическая сводка, вопросы, проверки, основания и
неизвестные. Справа доступны камеры, радио и датчики, ниже — лента событий и схема
этажа. Интерфейс и ответы на английском. Код: ES modules, CSS, MediaSource и
локальный Python gateway, без npm-зависимостей.

## Запуск всей цепочки

Терминал 1, из `agent-service/`: настроить 1Password и `.env` по
[OpenRouter handoff](../../agent-service/docs/OPENROUTER.md), затем:

```sh
uv sync --frozen
op run --env-file=.env -- .venv/bin/python -m uvicorn \
  fire_agents.api:create_app --factory --host 127.0.0.1 --port 8012
```

Текущие модели: `google/gemini-3.1-flash-lite` / `minimal`, fallback
`openai/gpt-5.6-luna` / `none`; четыре обработчика событий
(`FIRE_EVENT_WORKERS=4`), вывод до 1200 токенов, `FIRE_PROVIDER_SORT=latency`.

Терминал 2, из корня репозитория:

```sh
python3 dashboard/live/server.py \
  --port 8790 \
  --state-config /absolute/private/state-api-client.json \
  --platform-config /absolute/private/platform-client.json \
  --agent-url http://127.0.0.1:8012 \
  --live-pipeline --analysis-interval 3 \
  --pipeline-work-dir agent-service/work/live-pipeline
```

Открыть `http://127.0.0.1:8790/?run=<согласованный-run-UUID>`, чтобы подключиться
к существующему запуску. Без `run` интерфейс создаёт отдельный paused run; Play
запускает его. ID остаётся в URL. Настройки позволяют выбрать другой run или
создать новый. Play, pause, seek и reset действуют на выбранный run и всех его
подписчиков. Сам импортёр не отправляет команды управления State API.

Конфигурации сохраняются **вне репозитория**, с правами `0600`. Форматы:

```json
{
  "base_url": "https://api.aitinkerers.space/api/v1",
  "read_token": "<State read token>",
  "control_token": "<State control token>"
}
```

```json
{
  "base_url": "https://platform.aitinkerers.space",
  "api_key": "<Platform X-API-Key>"
}
```

Токены берутся из доступного 1Password: `State Machine API`,
`Platform API_KEY (state-consumer / X-API-Key)`, а модель — из
`OpenRouter API Key - demo`, поле `credential`. Альтернативы файлам:
`STATE_API_URL`, `STATE_READ_TOKEN`, `STATE_CONTROL_TOKEN`, `PLATFORM_API_URL`,
`PLATFORM_API_KEY`. Постоянные ключи не передаются браузеру. Если используется
`FIRE_UI_SESSION_TOKEN`, одно значение нужно агенту и gateway.

Для этого режима запускать `server.py` без `--demo-agent`. `run_local.py` предназначен
для отдельного fixture-демо и автоматически добавляет этот флаг.

## Как идут данные

```text
State snapshot + опубликованная история + SSE
  → gateway pipeline.py
  → Platform POST /ingest/telemetry: сохранение и настоящие reading IDs
  → локальный агент: события + часы сценария
  → /agent/v1/state и SSE → Briefing / Checks / Questions
```

Перед подпиской импортёр восстанавливает уже опубликованную историю выбранного
поколения. Исходное наблюдение сохраняется в Platform
`payload.state_observation`, а привязка к сценарию — в
`provenance.state_machine`: `run_id`, `generation`, `evidence_id`,
`observed_sim_time_ms`, `received_sim_time_ms`. Агент получает ID действительно
сохранённой записи; UI позволяет открыть её и исходное наблюдение.

Устройства импортируются в отдельном пространстве
`sm-live-<run_id>-g<generation>-<device_id>`. Контекст агента —
`state-<run_id>-g<generation>`, его generation `0`, subject `all`. Смена поколения
State создаёт другой контекст, сохраняя прежние записи. Поле platform `ts` может
содержать время получения; позиция исторического аудио и часы агента определяются
сохранёнными simulation offsets.

Журнал в `--pipeline-work-dir` сохраняет статус отправки и полученные reading IDs.
При неоднозначном результате ingestion импортёр сначала сверяет сохранённые записи;
он не должен слепо повторять принятую запись. Сохраняйте журнал вместе с БД агента,
не запускайте параллельно два gateway-импортёра для одного run. Прежняя БД и
отдельный серверный bridge Palisades остаются сохранены.

В этом режиме gateway сам импортирует события и продвигает часы; дополнительный
platform-sync агента через `FIRE_PLATFORM_SCOPE` не нужен. Публичный MCP платформы
доступен по `https://platform.aitinkerers.space/mcp-server/mcp`, но критический путь
дашборда использует REST. `/api/platform/…` остаётся ограниченным read-only proxy
для браузера; запись выполняет серверный pipeline.

## Автоматический Briefing и ограничения

После новых импортированных данных запускается сводка, не чаще чем раз в 3 секунды.
Один автоматический запрос ожидает завершения; новый не создаёт очередь, пока есть
обрабатываемый вопрос. Пользователь может задавать свои вопросы, смотреть проверки,
источники, unknowns, coverage и queries, отменять и повторять запросы.

Сводка использует до **20 событий** из последних **500 кандидатов**, суммарно до
**24 000 символов**: последние показатели разных источников и недавнее радио.
Это не анализ полной истории. Отсутствие события в такой выборке не доказывает,
что события не было. Для тренда нужны несколько последовательных измерений.
Камеры дают агенту метаданные фрагментов, а не результат просмотра изображения.
Распознавание видео и новая ASR здесь не запускаются.

Copilot показывает состояние импорта, published/imported/skipped, время входных
данных, задержку ответа и отставание сводки. `live` у pipeline означает подключённый
импорт, а не гарантию полноты уже обработанного агентом контекста. Счётчики сырых
событий не выдаются за количество завершённых LLM-проверок.

Предварительные замеры: Gemini 3.1 Flash Lite — 1,83–2,01 с на тестовом наборе из
20 событий; в подключённой цепочке наблюдался автоматический ответ примерно за
3 с. Это небольшая проверка, не SLA и не приёмка длительного воспроизведения.
Подробности и компромисс скорости/полноты — в [OpenRouter handoff](../../agent-service/docs/OPENROUTER.md).

## Просмотр источников

- State snapshot + SSE, восстановление после разрыва/смены generation;
  play/pause/reset/seek, скорости 1×/10×/60×.
- История опубликованных наблюдений: фильтры, поиск, JSON/provenance, экспорт;
  первые 100 строк и кнопка «Show 100 more». История дедуплицируется с SSE.
- Две CCTV-камеры: один fMP4 HTTP-поток на камеру, раскладки, fullscreen,
  отдельный опубликованный видеофрагмент из ленты.
- Радио: AAC fMP4-поток, явное включение звука, готовая машинная расшифровка,
  повтор реплики из уже полученных байтов без дополнительного постоянного потока.
- Missing, stale, disconnected и null отображаются отдельно; отсутствие данных
  не превращается в нулевое количество людей или нормальное состояние.

Base2: синтетические видео и датчики, окна записи `[0,15)`, `[68,83)`, `[128,143)`,
`[176,191)` секунд. Между окнами плеер сохраняет последний кадр и отмечает отсутствие
новых кадров. Схема помещений условная. Историческое радио Palisades относится к
другому событию; provenance сохраняет эту композицию независимых источников.

Медиа подаются с задержкой примерно 2,15 с относительно часов сценария. Звук
слушать на 1×; на 10×/60× он приостановлен, текст и сенсоры продолжают поступать.
Повтор реплики идёт на 1×. Palisades transcript воспроизводится из пакета и помечен
как prerecorded machine text, не новая расшифровка эфира.

## Отдельное fixture-демо

Для проверки интерфейса без LLM и Data Platform:

```sh
python3 dashboard/live/run_local.py --state-config /absolute/private/state-api-client.json
```

Launcher использует агент на `127.0.0.1:8010` либо запускает его из
`agent-service/.venv`. Кнопки Request → Assign channel → Acknowledge работают в
отдельной сессии `dashboard-channel-demo-en`; fixture не анализирует State-поток.
Его тестовые reading IDs не являются записями платформы, а аудио нельзя подменять
Palisades. Ctrl+C останавливает только созданные launcher процессы.

Gateway и агент слушают loopback. Для публикации этого gateway требуется отдельная
аутентификация и HTTPS. Старые макеты `dashboard/docs/design/` сохранены.

Проверяются контексты и поколения, пропуски последовательности, null/0, дубли,
границы SSE и запрет выдачи ключей браузеру. Визуальная и сетевая приёмка описана
в [VALIDATION.md](VALIDATION.md), разбор продуктов и сервисов — в
[исследовании](../docs/research/LIVE_COMMAND_RESEARCH.md).
