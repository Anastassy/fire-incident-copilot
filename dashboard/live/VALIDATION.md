# Проверка живого Copilot · 12 сентября 2026

Проверена цепочка на настоящих сервисах: State API на Hetzner → локальный SSE
импортёр → Platform HTTPS → SDK agent с OpenRouter → браузерный Incident Copilot.
Это проверка составного демо, а не измерение точности распознавания пожара.

## Воспроизведение и задержка

- В существующем тестовом run поколение 4 проиграно от 02:19 до конца 03:26.
  Сводки создавались автоматически и включали отдельные выводы по датчикам и радио,
  ссылки на сохранённые reading IDs и неизвестные.
- После удаления последовательных GET из обычного пути ingestion проведено
  11 измерений на скорости 1×: доставка относительно часов State — медиана **759 мс**,
  минимум **252 мс**, максимум **2273 мс**. Это короткая локальная выборка, не SLA.
- Автоматические ответы в этой проверке обычно завершались за **2–3 секунды** после
  отправки запроса. Задержка всей сводки включает доставку, интервал обновления и inference.
  Во время обработки предыдущий завершённый ответ остаётся видимым.
- Проверены пауза, переподключение локального gateway с сохранённым журналом и
  переход в поколение 5 через seek. Старые 708 событий поколения 4 сохранены;
  UI очистил предыдущие ответы. Новая история импортирована только до выбранных 02:08.
- В поколении 5 воспроизведён интервал 02:08–02:26 на 1×. Агент выделил запрос
  канала, назначение V-Fire 25 и ответ-подтверждение; исходные IDs принадлежат G5.
  Идентичность говорящего и переход всех членов группы остаются неподтверждёнными.
- Две камеры и основное радио в браузере достигли readyState=4 без ошибок декодирования.
  Переход из вывода агента к источнику сопоставляет run, generation и evidence ID.
  Исходный аудиоинтервал 02:03–02:05 воспроизведён до конца, readyState=4, без ошибки.
- Ручной вопрос о назначенном радиоканале получил английский ready-ответ с
  отдельными источниками назначения и подтверждающей реплики, без подмены контекста.

## Проверки кода

- Agent service: **74 pytest-теста**.
- Pipeline и gateway: **23 unittest-теста**.
- Browser state и Copilot UI: **15 Node-тестов**.
- Изолированные Platform MCP/ingestion: **11 pytest-тестов**, без подключения тестов к рабочей БД.
- Проверены различие null/0, ограничение будущими событиями, изоляция поколений,
  восстановление без повторного ingestion, реальные reading IDs, исключение
  поздних ответов из другого контекста и сохранение radio при плотной телеметрии.

## Что остаётся за пределами проверки

Видео здесь показывается как исходное CCTV; модель не получает кадры для vision.
Радио транслируется вместе с готовой машинной расшифровкой из пакета: нового ASR
в этом сервисе нет. Все исходные слова, таймкоды и provenance сохраняются;
только представление для LLM сокращает повторы. Анализ использует ограниченную
выборку до 20 событий из 500 кандидатов, а не полную историю инцидента.

Основная модель — Gemini 3.1 Flash Lite, резервная — GPT-5.6 Luna. Fallback покрыт
тестами ошибок/таймаута/невалидного ответа и отмены. Обе модели проверены реальными
запросами; принудительное переключение в работающем браузерном replay не проводилось.
Точность фактов и атрибуции говорящих по ручному эталону не измерялась.

# Приёмка Firewatch

12 сентября 2026. Рабочая база: main `8294ebf` (включая платформу, новый channel reducer и platform polling). Изменения реализации ограничены `dashboard/live/`; исследование добавлено в `dashboard/docs/research/`.

## Выполнено

**Автоматически: 30 тестов прошли.**

- 6 browser-independent JS тестов: старые generation/run, разрыв sequence, дедупликация истории, null/zero, контекст/ревизии агента, SSE с побайтовым разбиением UTF-8 и CRLF.
- 3 теста gateway: постоянные ключи не выдаются в config/static, серверная подстановка токенов и Range, запрет cross-origin POST, закрытых API-маршрутов и записи в платформу.
- 21 существующий тест агента (`tests/test_ui.py`, `tests/test_channels.py`): его API, вопросы, отмена, границы контекста и фазы радиоканала. Один deprecation warning зависимости Starlette/AnyIO; ошибок нет.

**Через браузер и реальный State API:**

- Создан отдельный UI run Base2, без изменения запусков коллег. Перезагрузка страницы повторно подключается к UUID из URL.
- Оба H.264-потока и AAC декодируются; `readyState=4`, время плееров движется вместе с часами сценария с задержкой подачи. Звук явно включается кнопкой; подтверждён unmuted/playing на 1×.
- Пауза останавливает время и медиа. Reset переключил G0 → G1, обнулил ленту, реплики и медиабуферы.
- Полный прогон на 60×: **811 наблюдений, 43 транскрипции** в UI; независимо прочитанный серверный snapshot/history даёт те же числа, `dropped=0`.
- Полный прогон на 10×: те же **811 / 43**. Сервер отдельно сообщает 19 подавленных источником наблюдений и один transport control — это сценарная потеря связи, не потеря доставки SSE.
- Seek создал G2 и корректно вернул часы/камеры примерно к 02:19. История перечитана для нового поколения, видео позиционировано на уже полученные кадры примерно 02:16,8.
- Переключение «Обе камеры / Gradas» меняет видимость плиток. Из camera observation открывается соответствующий опубликованный двухсекундный MP4 (`readyState=4`, duration=2).
- Реплика 00:00,620–00:10,700 повторно воспроизводится из полученного аудиобуфера; наблюдались advancing currentTime, `paused=false`, `readyState=4`. Аудио не загружает будущие данные.
- Поиск `TMP-B2` отбирает сенсорные события; видны отдельные фильтры и общий счётчик. Все 811 наблюдений остаются доступны через историю и JSON-экспорт.
- Проверена компактная раскладка: при фактической ширине документа 381 CSS px `scrollWidth=clientWidth=381`. Камеры и секции становятся вертикальными. Временная настройка viewport снята. Финальная визуальная проверка проведена также в обычной ширине браузера.
- В завершённых проверках консоль браузера не содержала ошибок приложения.

**Через настоящий локальный API агента, FixtureEngine:**

- Синтетическая сессия `dashboard-channel-demo` проходит три фазы: запрос без назначения → V-Fire 25 назначен, ответа нет → отдельная подтверждающая реплика. Одна карточка обновляет ревизии 0 → 2 → 4.
- UI показывает фактическое `insufficient_data`, затем `supported`, сохраняет ограничения про неизвестную личность говорящего и отсутствие доказательства перехода всех участников.
- Вопрос отправляется через `/agent/v1/questions`, переходит в ready и возвращает реальные DTO API. Тип тестового обработчика и отсутствие смыслового анализа написаны в самом экране.
- Переход по evidence открывает исходный текст, synthetic origin, verification и reading ID. `audio=missing` остаётся missing; историческое Palisades-аудио сюда не подставляется.

## Ограничения этой приёмки

Не проверены реальные вызовы SDK/модели, семантическая точность распознавания, развёрнутый Data Platform и его импорт в агента, media resolver агента, сторонние браузеры и публичное размещение UI. По сообщению пользователя URL этих backend-сервисов ещё не готовы. Локальная панель реализует их UI API, но её тестовая сессия не анализирует State run.

Звук ускоренного replay намеренно приостановлен: для непрерывного прослушивания выбрать 1×. Между четырьмя окнами CCTV нет кадров. Схема Base2 условная, видеоматериалы синтетические. Радио — отдельная историческая запись с заранее подготовленной машинной транскрипцией.

Переключатель дополнительных радиоисточников включается только при нескольких audio streams; в приёмочном Base2 поток один, поэтому многоканальное переключение отдельно не проверялось. JSON-экспорт проверен по реализации, без отдельного теста браузерной загрузки файла. Кнопка отмены использует API; её гонки и идемпотентность проверены тестами сервиса, а не ручным быстродействием FixtureEngine.

Английские тестовые сообщения помещаются в отдельную сессию `dashboard-channel-demo-en`; старые сессии и исходные записи не менялись. В браузере проверены основной экран, настройки, отсутствие кириллицы в видимом тексте и английский ответ FixtureEngine. Консоль без ошибок; 6 JS и 3 gateway-теста повторно прошли.

## Экран с акцентом на Copilot

Переработка поверх main `e2664a2`: Copilot занимает основную колонку и первый экран; вопрос расположен над рабочими вкладками. Briefing открывает последнюю фактическую проверку, а её основания и ограничения доступны сразу. Источники State размещены в соседней колонке, история и схема — ниже.

Проверено через браузер и текущий локальный API:

- Из «Link evidence» открывается список доказательств именно текущего контекста агента; переход ведёт к исходной реплике, reading ID и provenance. Отсутствующее аудио остаётся missing.
- Кнопки Assign channel и Acknowledge обновили ту же карточку v0 → v2 → v4; получены три связанных источника и supporting report, ограничения сохранены.
- Английский вопрос отправлен через API, получен ready-ответ с тремя источниками. Вкладки Questions и Briefing переключаются; счётчики соответствуют snapshot.
- Номера Source 1 / 2 / 3 согласованы между утверждениями и индексом доказательств. Видимый текст не содержит кириллицы.
- Оба видео и радио после перезагрузки имеют readyState=4; существующий State run остаётся на паузе, generation и позиция не изменены. Переключение Gradas / Both cameras работает.
- На узком экране Copilot расположен перед источниками, горизонтального переполнения документа нет. Временный viewport сброшен после проверки.
- Повторно прошли 6 JS и 3 gateway-теста. Консоль приложения без ошибок. Backend анализа не изменялся; проверки ответа относятся к FixtureEngine.

## Подключение OpenRouter

После проверки FixtureEngine дашборд переключён на отдельный SDKEngine на
`127.0.0.1:8012`. Основная модель — GPT-6 Astra, fallback — Fable 5.1; точные ID
выводятся из health активного движка. Ключ прочитан из 1Password серверным
процессом. Подробные параметры и live smoke описаны в
[документе агента](../../agent-service/docs/OPENROUTER.md).

Три явно синтетические реплики в `dashboard-openrouter-demo` обработаны настоящей
моделью, без fixture-аннотаций: jobs=done, действия channel_requested,
channel_assigned, channel_acknowledged. Вопрос из браузера получил ready-ответ
на английском, со ссылками на все три исходных сообщения и явными ограничениями
о неизвестном говорящем, отсутствии аудио и синтетическом происхождении. По ссылке
открывается именно соответствующий source; audio=missing не подменяется Palisades.
Оба видео и радио сохранили readyState=4 и прежнюю позицию paused run. Кириллицы и
ошибок консоли нет, горизонтального переполнения в обычной ширине нет.

Полностью прошли 59 тестов agent-service и 9 тестов dashboard/gateway. Реальная
автоматическая передача State → Data Platform → agent в этой сессии не проверена:
порт 8000 не ответил на health, SDK-контекст явно отделён от State run в интерфейсе.
