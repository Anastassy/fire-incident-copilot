# Приёмка Firewatch

12 сентября 2026. Рабочая база: main `8294ebf` (включая платформу, новый channel reducer и platform polling). Изменения реализации ограничены `dashboard/live/`; исследование добавлено в `dashboard/docs/research/`.

## Выполнено

**Автоматически: 30 тестов прошли.**

- 6 browser-independent JS тестов: старые generation/run, разрыв sequence, дедупликация истории, null/zero, контекст/ревизии агента, SSE с побайтовым разбиением UTF-8 и CRLF.
- 3 теста gateway: постоянные ключи не выдаются в config/static, серверная подстановка токенов и Range, запрет cross-origin POST, закрытых API-маршрутов и записи в платформу.
- 21 существующий тест агента (`tests/test_ui.py`, `tests/test_channels.py`): его API, вопросы, отмена, границы контекста и фазы радиоканала. Один deprecation warning зависимости Starlette/AnyIO; ошибок нет.

**Через браузер и реальный State API:**

- Создан отдельный UI run Base2, без изменения запусков коллег. Перезагрузка страницы повторно подключается к UUID из URL.
- Оба H.264-потока и AAC декодируются; `readyState=4`, время плееров движется вместе с часами сценария с задержкой подачи. Звук явно включается кнопкой; подтверждён unmuted/playing на 1×.
- Пауза останавливает время и медиа. Reset переключил G0 → G1, обнулил ленту, реплики и медиабуферы.
- Полный прогон на 60×: **811 наблюдений, 43 транскрипции** в UI; независимо прочитанный серверный snapshot/history даёт те же числа, `dropped=0`.
- Полный прогон на 10×: те же **811 / 43**. Сервер отдельно сообщает 19 подавленных источником наблюдений и один transport control — это сценарная потеря связи, не потеря доставки SSE.
- Seek создал G2 и корректно вернул часы/камеры примерно к 02:19. История перечитана для нового поколения, видео позиционировано на уже полученные кадры примерно 02:16,8.
- Переключение «Обе камеры / Gradas» меняет видимость плиток. Из camera observation открывается соответствующий опубликованный двухсекундный MP4 (`readyState=4`, duration=2).
- Реплика 00:00,620–00:10,700 повторно воспроизводится из полученного аудиобуфера; наблюдались advancing currentTime, `paused=false`, `readyState=4`. Аудио не загружает будущие данные.
- Поиск `TMP-B2` отбирает сенсорные события; видны отдельные фильтры и общий счётчик. Все 811 наблюдений остаются доступны через историю и JSON-экспорт.
- Проверена компактная раскладка: при фактической ширине документа 381 CSS px `scrollWidth=clientWidth=381`. Камеры и секции становятся вертикальными. Временная настройка viewport снята. Финальная визуальная проверка проведена также в обычной ширине браузера.
- В завершённых проверках консоль браузера не содержала ошибок приложения.

**Через настоящий локальный API агента, FixtureEngine:**

- Синтетическая сессия `dashboard-channel-demo` проходит три фазы: запрос без назначения → V-Fire 25 назначен, ответа нет → отдельная подтверждающая реплика. Одна карточка обновляет ревизии 0 → 2 → 4.
- UI показывает фактическое `insufficient_data`, затем `supported`, сохраняет ограничения про неизвестную личность говорящего и отсутствие доказательства перехода всех участников.
- Вопрос отправляется через `/agent/v1/questions`, переходит в ready и возвращает реальные DTO API. Тип тестового обработчика и отсутствие смыслового анализа написаны в самом экране.
- Переход по evidence открывает исходный текст, synthetic origin, verification и reading ID. `audio=missing` остаётся missing; историческое Palisades-аудио сюда не подставляется.

## Ограничения этой приёмки

Не проверены реальные вызовы SDK/модели, семантическая точность распознавания, развёрнутый Data Platform и его импорт в агента, media resolver агента, сторонние браузеры и публичное размещение UI. По сообщению пользователя URL этих backend-сервисов ещё не готовы. Локальная панель реализует их UI API, но её тестовая сессия не анализирует State run.

Звук ускоренного replay намеренно приостановлен: для непрерывного прослушивания выбрать 1×. Между четырьмя окнами CCTV нет кадров. Схема Base2 условная, видеоматериалы синтетические. Радио — отдельная историческая запись с заранее подготовленной машинной транскрипцией.

Переключатель дополнительных радиоисточников включается только при нескольких audio streams; в приёмочном Base2 поток один, поэтому многоканальное переключение отдельно не проверялось. JSON-экспорт проверен по реализации, без отдельного теста браузерной загрузки файла. Кнопка отмены использует API; её гонки и идемпотентность проверены тестами сервиса, а не ручным быстродействием FixtureEngine.
