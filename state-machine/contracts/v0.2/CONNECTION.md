# Подключение к серверу · 0.2.2

Базовый URL: **http://127.0.0.1:8787/api/v1**.
[Проверка доступности без токена](http://127.0.0.1:8787/api/v1/health).

Сервер отдаёт исходные данные и готовую расшифровку Palisades из пакета. Состояния
и текст — SSE, видео/аудио — непрерывные HTTP-потоки. Сервер не запускает распознавание.
[Подключение синхронного аудио и текста Palisades](PALISADES.md).

## Доступ

Для локального экземпляра выполните `scripts/setup_local.py` из корня компонента.
Адрес и случайные `read_token` / `control_token` находятся в `var/private/client.json`.
Для чужого экземпляра владелец выдаёт адрес и application token отдельно от репозитория.

Токен передаётся как `Authorization: Bearer <token>`. `read_token` разрешает чтение,
SSE и медиа, `control_token` — также управление. Ключи действуют 30 дней с генерации.
CORS разрешает localhost/127.0.0.1/::1 и точные origin из `extra_origins` конфигурации.
Нативный браузерный EventSource не устанавливает Authorization: используйте streaming
fetch с разбором SSE или свой серверный прокси.

## Один запуск для интерфейса и внешнего обработчика

1. Прочитать GET `/capabilities` и `/scenarios`.
2. Создать POST `/runs` с Idempotency-Key UUID и телом
   `{"scenario_id":"degraded","speed":1}`. В ответе run_id, generation=0, paused.
3. Все потребители подключаются к **одному run_id**. Если каждый создаст свой,
   у них будут независимые часы и состояние.
4. Открыть GET `/runs/{run_id}/stream` один раз. Первый SSE-кадр — snapshot,
   затем сервер сам присылает события. Опрос `/snapshot` по таймеру не нужен.
5. Один раз прочитать GET `/runs/{run_id}/media-streams`; открыть content_url
   выбранных устройств. Получается одно длительное соединение на канал.
6. Кнопки отправляют POST `/runs/{run_id}/commands`. Пример Play:

```json
{
  "command_id": "569f86c0-3555-4f0a-9b9f-539258dcb570",
  "expected_generation": 0,
  "action": "play"
}
```

Для нового действия создавайте новый command_id; повтор после сетевой ошибки
использует прежний ID и прежнее тело. Pause — action=pause. Reset — action=reset;
он увеличивает generation и закрывает старые медиапотоки.

## Что означает «стрим»

```text
Клиент ── один GET SSE ────────► State Machine
Клиент ◄─ новые JSON-события ── State Machine

Клиент ── один GET на канал ──► State Machine
Клиент ◄─ init, fragment, … ─── State Machine

Play/Pause/Reset ── POST ─────► State Machine
```

На паузе бинарное соединение остаётся открытым, новых samples нет. После Play
они поступают по тем же соединениям. Уже загруженный буфер плеера UI останавливает
сам по событию run.updated. После Reset/seek подключиться заново для новой generation.

Медиа — fragmented MP4: H.264 для видео, AAC для аудио. Это не HLS-плейлист и
не WebSocket. Поток читается обычным потоковым HTTP-клиентом/демультиплексором;
для браузера нужен совместимый MP4-плеер или MediaSource. Внешний интерфейс и его
плеер не входят в этот сервер. При 10×/60× доставка ускоряется; воспроизведение
и буферизацию клиент синхронизирует отдельно.

GET Media с Range сохранён для загрузки отдельного исторического фрагмента.
Он не требуется для непрерывной передачи по media-streams.

## Данные и ограничения поставки

Стандартная сборка создаёт три сценария (`normal`, `escalation`, `degraded`), две
синтетические камеры и два тестовых тона по 6 секунд. Показания датчиков и СКУД —
авторские фикстуры. Отдельная строка текста сопровождает тон и явно не является ASR.
Сценарии идут 600/660 секунд, а короткие медиа завершаются раньше. Автоповтора нет.

Импортёр `scripts/import_repository_radio.py` добавляет `palisades-focus`: 206 секунд
радио, 43 готовых текстовых сегмента, те же синтетические камеры и датчики. Полный
десятиминутный вариант требует отдельного внешнего пакета. Состав всегда уточняйте
через `/scenarios` и `/runs/{run_id}/media-streams`; подробности — [PALISADES.md](PALISADES.md).

Число людей — null, пока нет наблюдения people_count от прямого источника. Фикстуры
examples вымышлены и описывают формат, а не точные значения конкретного bundle.
Распознавание и интерфейс относятся к другому компоненту.

Run хранится 24 часа. После перезапуска сохраняются run_id, generation, снимок и
журнал; воспроизведение восстанавливается на паузе. Лимиты по умолчанию: 16 runs,
24 потоковых соединения суммарно. Инструкции сборки и проверок — в
[README компонента](../../README.md).
