# State Machine: поток исходных данных

Самостоятельный Python-сервис для воспроизведения состояния виртуального здания.
Датчики, камеры, СКУД и радио используют общие часы запуска (`run_id`). После Play
состояния и готовый текст идут через SSE, аудио и видео — по длительным HTTP-соединениям.
Сервис сохраняет запуски, снимки и журнал в SQLite. Распознавание и выводы об инциденте
выполняет внешний слой.

Этот компонент добавлен отдельно от `agent-service/` и `agent-ui-contract-v0.1/`.
Существующий агент использует свой Platform MCP; адаптер между ним и этим API ещё
не подключён. Контракт State API **0.2.2** (схема **0.2**) описывает входные данные,
а Agent → UI **0.1** — результаты обработки. Это разные границы системы.

## Быстрый локальный запуск

Нужны Python 3.10+ и FFmpeg/ffprobe с H.264/AAC. Рабочий сервер использует только
стандартную библиотеку Python. Команды выполняются из этой папки:

```bash
cd state-machine
python3 scripts/build_demo_bundle.py
python3 scripts/setup_local.py
python3 -m state_api --bundle var/demo-bundle --database var/private/state.sqlite --config var/private/server.json --port 8787
```

Первые две команды создают локальные входные данные и независимые случайные токены.
Повторный `setup_local.py` сохраняет существующие ключи. Сборщик требует новый каталог
вывода: для другой версии используйте `--output var/demo-bundle-v2`.
Сервер слушает `127.0.0.1:8787`; [health](http://127.0.0.1:8787/api/v1/health) доступен
без авторизации. Токены находятся в `var/private/client.json`, сервер хранит их хеши
в `server.json`. Весь `var/` исключён из Git.

В другом терминале, из этой же папки:

```bash
python3 scripts/api.py GET /scenarios
python3 scripts/api.py POST /runs '{"scenario_id":"degraded","speed":1}'
# Подставьте run_id из ответа; новый запуск находится на паузе.
python3 scripts/api.py POST /runs/RUN_ID/commands '{"expected_generation":0,"action":"play"}'
python3 scripts/api.py GET /runs/RUN_ID/snapshot
python3 scripts/api.py POST /runs/RUN_ID/commands '{"expected_generation":0,"action":"pause"}'
```

CLI читает токен из файла, добавляет UUID для создания run и команд. Для повторения
одного запроса после сетевой ошибки сохраните исходные `command_id` / `Idempotency-Key`.
Токены действуют 30 дней с генерации; замена ключей — отдельная операция владельца сервиса.

## Что воспроизводится

| Bundle / сценарий | Данные | Время |
|---|---|---|
| `demo-bundle`: `normal`, `escalation`, `degraded` | Авторские показания, СКУД, две одноцветные камеры, два тестовых тона | Датчики 600/660 с; каждое медиа 6 с |
| `palisades-bundle`: те же сценарии + `palisades-focus` | Радиозапись и готовый текст из уже имеющегося пакета репозитория; остальные источники синтетические | Palisades 206 с, 43 текстовых сегмента |

Минимальные `normal` и `escalation` используют одинаковую тестовую телеметрию;
`degraded` дополнительно показывает молчащий и отключённый датчики. Это транспортные
фикстуры, не физическая модель пожара. Текст в синтетическом сценарии подписан как
авторская строка, сопровождающая тон. Прямого подсчёта людей в демо нет: `count=null`.
Событие пропуска не доказывает присутствие человека. Missing, stale, disconnected
сохраняют разные значения; последние показания не обнуляются при потере связи.

Для настоящего радио используйте существующий `data/demo/palisades-radio-demo/`:

```bash
python3 scripts/import_repository_radio.py
# Остановите только свой локальный процесс. Новый bundle — отдельная БД.
python3 -m state_api --bundle var/palisades-bundle --database var/private/palisades.sqlite --config var/private/server.json --port 8787
```

Создавайте run с `scenario_id=palisades-focus`. Импорт декодирует имеющийся MP3 в WAV,
сохраняет SHA-256, происхождение и атрибуцию, формирует PCM-фрагменты и поток AAC/fMP4.
Исходные файлы не меняются. Расшифровка уже выполнена в исходном пакете; сервер
публикует её по времени, сохраняя слова и таймкоды. Нового ASR здесь нет.
Аудио и виртуальное здание — условное совмещение независимых источников.
**Audio Provided by Broadcastify**, условия и источник — в
[имеющемся пакете](../data/demo/palisades-radio-demo/README.md).

Полный десятиминутный Palisades не входит в репозиторий. Для внешнего полного пакета
с `manifest.json`, `SHA256SUMS`, WAV и JSON есть `scripts/add_palisades_bundle.py`:
передайте `--package /path/to/package --base var/demo-bundle --output var/full-bundle`.
Список доступных сценариев всегда берите из `/scenarios`.

## Подключение команды

1. Один управляющий клиент создаёт run и передаёт `run_id` остальным потребителям.
2. Каждый открывает `/runs/{run_id}/stream` с Bearer-токеном чтения: сначала snapshot,
   затем JSON-события SSE. Регулярный опрос состояния не требуется.
3. Из `/runs/{run_id}/media-streams` клиент получает подписанные `content_url` и открывает
   по соединению на нужный канал. Видео — H.264, аудио — AAC, контейнер fragmented MP4.
4. Play/Pause/Reset/seek управляют общими часами. Смена generation закрывает старое
   медиа; клиент очищает старые данные и подключает новые потоки.

После конца файла поток завершается; автоматического повтора нет. Пауза останавливает
выдачу будущих фрагментов, а уже накопленный буфер UI останавливает сам. Браузеру нужен
плеер с поддержкой fMP4/MediaSource. Встроенный `EventSource` не позволяет передать
Bearer-заголовок: используйте SSE-клиент на основе streaming fetch или серверный прокси.
Плеер и интеграционный адаптер не входят в эту папку.

## Проверка

Тесты сами создают временные bundle и базы. Они проверяют реальные HTTP/SSE-соединения,
детерминированный replay, авторизацию, CORS, идемпотентность, границы медиа,
восстановление SQLite, таймкоды и неизменность всех 43 фраз Palisades.
Для этих тестов нужен уже включённый в репозиторий радиоэпизод и FFmpeg.

```bash
uv run --with-requirements requirements-dev.txt python -m unittest discover -s tests -v
uv run --with-requirements requirements-dev.txt python contracts/tools/validate_contract.py
```

Альтернатива `uv`: отдельный virtualenv, `pip install -r requirements-dev.txt`, затем
те же команды Python. Изменения схем вносятся в `contracts/tools/build_contract.py`;
запуск этого файла пересоздаёт OpenAPI и синтетические примеры.

Запуски живут 24 часа, лимиты по умолчанию — 16 runs и 24 потоковых соединения.
После перезапуска сохранённый run восстанавливается на паузе. Это демонстрационный
сервис; высокая нагрузка и работа внешнего браузерного плеера этими тестами не подтверждены.
Исследования, Blender-сцены, локальные базы и инфраструктурные ключи в поставку не входят.
