# Приёмка и текущее состояние

## Что проверяет Настя на фикстурах

1. Отправка question-create; отображение answer-queued, затем answer-ready.
2. Каждое утверждение открывает соответствующий Evidence. Missing audio отображается без работающей кнопки Play.
3. card-checking заменяется card-supported: одна карточка с тем же hypothesis_id.
4. answer-without-confirmation не отображается как подтверждение. answer-group-unknown не утверждает переход всей группы.
5. answer-error отличим от insufficient_data; вопрос можно повторить.
6. Повтор старой revision не откатывает экран; новый generation удаляет активные ответы и останавливает плеер.
7. Разрыв SSE сохраняет данные с временем обновления, затем GET state восстанавливает представление.
8. Нет severity, тактических команд и выдуманных позиций. Все текстовые поля выводятся как текст, не исполняемый HTML.

## Что реализовано сейчас

Прототип имеет синхронный POST /agent/questions с session_id/generation/text и другим ответом; есть локальные sessions/events/clock. Это НЕ реализация нового /agent/v1 контракта. Не подключать UI к старому методу как к готовому новому API.

Есть сохраняемые задачи, SDK-агенты, MCP-адаптер, отдельный publisher и локальные тесты. Не реализованы новые DTO/методы, асинхронные вопросы, UI SSE, evidence resolver, авторизация и полный snapshot в описанном формате. Первое действие нашей следующей итерации — реализовать этот контракт на фикстурах с теми же JSON-структурами.

## Что нужно согласовать перед живым подключением

Base URL нашего сервиса, session/proxy, выдача context, формат нормализованной реплики платформы, доступность медиа/resolver. Полный исходный журнал подключает Настя из Data Platform; агент его не фильтрует за оператора. Scope пакет ссылается на State Machine 0.2.2, тогда как имеющийся сырой API-пакет описывает прежний draft: не считать более новую реализацию проверенной.

## Приёмка реального запуска

Оба вопроса и карточка получают результат реальными запросами к текущему срезу. Отсутствие подтверждающей реплики меняет ответ. Нет будущих данных. Аудио открывается на нужном интервале, содержание прослушано человеком. Incidents сохраняются в платформе, состояние публикации честно отражается в UI. Этот пакет проверяет только форму контракта и примеры, а не перечисленные свойства живой системы.
