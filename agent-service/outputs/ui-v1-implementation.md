# UI v1 — локальная реализация

Контракт `/agent/v1` реализован в `agent-service/` репозитория fire-incident-copilot. Английские README и комментарии коммитов предназначены для команды хакатона.

Работают: асинхронный вопрос, опрос результата, отмена, snapshot, одна обновляемая карточка, контекстное evidence и SSE-сигналы. Идемпотентный ключ не создаёт второй вопрос. После reset старые ответы и доказательства недоступны в новом контексте. Восстановление незавершённого вопроса идёт через сохранённую очередь и lease.

Ответы, карточки, snapshot, evidence и ошибки проверяются на соответствие схемам исходного пакета v0.1. Статусы публикации и результат проверки независимы. Непроверенный платформенный статус остаётся null. На этом этапе запросы читают локальный импорт данных; в queries записывается реальное local_event_query, а не выдуманный MCP-вызов.

Аудио: endpoint evidence уже работает, но resolver отсутствует. UI получает pending/missing без playback_url. Это позволяет подключить и проверить состояния интерфейса, но не является готовностью прослушивания реального эпизода.

Первый запуск: из agent-service выполнить `uv sync --frozen`, затем `uv run uvicorn fire_agents.api:create_app --factory --host 127.0.0.1 --port 8010`. Отдельно `uv run python -m fire_agents.ui_demo assign`; контекст demo_context_id=ui-demo, generation=0, subject_id=all. Команда complete добавляет завершение, reset начинает новое поколение. Данные синтетические, не проверенный Palisades.

По умолчанию FixtureEngine, никакие ответы не выдаются за реальную работу модели. Для OpenAI нужны переменные окружения, описанные в README. Живая Data Platform, реальная модель, аудио и сетевое развёртывание не проверялись. Для сетевого показа нужен согласованный proxy/auth; локальный режим доступен только на loopback.

Следующий атомарный шаг: Настя подключает экран к локальному v1 на этих данных. После этого заменяем источник данных и подключаем media resolver. Отдельный экран наблюдения за агентами не строился.
