# OpenRouter: быстрый агент и fallback

Текущая конфигурация: основная модель `google/gemini-3.1-flash-lite` с
`reasoning.effort=minimal`, резервная — `openai/gpt-5.6-luna` с `none`.
SDKEngine использует JSON Schema, `provider.require_parameters=true` и выбор
провайдера по задержке. Ключ находится только в процессе агента; OpenAI Agents SDK
tracing для OpenRouter отключён.

## Запуск с 1Password

Из `agent-service/`:

```sh
uv sync --frozen
cp .env.openrouter.example .env
# В .env заменить YOUR_VAULT на имя доступного хранилища.
op run --env-file=.env -- .venv/bin/python -m uvicorn \
  fire_agents.api:create_app --factory --host 127.0.0.1 --port 8012
```

В примере окружения указаны:

```dotenv
FIRE_ENGINE=sdk
FIRE_PROVIDER=openrouter
FIRE_MODEL=google/gemini-3.1-flash-lite
FIRE_FALLBACK_MODEL=openai/gpt-5.6-luna
FIRE_REASONING_EFFORT=minimal
FIRE_FALLBACK_REASONING_EFFORT=none
FIRE_PROVIDER_SORT=latency
FIRE_MAX_OUTPUT_TOKENS=1200
FIRE_EVENT_WORKERS=4
FIRE_OUTPUT_LANGUAGE=en
FIRE_DB_PATH=work/openrouter-live.sqlite3
OPENROUTER_API_KEY=op://YOUR_VAULT/OpenRouter API Key - demo/credential
```

1Password CLI должен быть авторизован. Для service account используется
`OP_SERVICE_ACCOUNT_TOKEN` вне репозитория. `op run` разрешает ссылку на запись
`OpenRouter API Key - demo`, поле `credential`. `.env` исключён из Git; реальный
ключ в него копировать не нужно. Другой secret manager может передать
`OPENROUTER_API_KEY` через окружение.

`FIRE_EVENT_WORKERS=4` запускает четыре обработчика событий; вопросы обслуживает
отдельный обработчик. Извлечение радио-фактов вызывает модель, обычные сенсорные
события сохраняются без LLM-экстракции. Разбор общей ситуации использует и сенсоры,
и радио. Выбирайте отдельный `FIRE_DB_PATH`; прежние БД не удалять.

## Соединение с источниками

Полный запуск gateway и приватные конфигурации описаны в
[инструкции дашборда](../../dashboard/live/README.md). Рабочая цепочка:

```text
State API: опубликованная история + SSE
  → dashboard/live/pipeline.py
  → Platform REST: сохранённые TelemetryReading и настоящие reading IDs
  → локальный SDKEngine: события, часы контекста, вопросы
  → /agent/v1: проверки, автоматический Briefing, evidence
```

Gateway запускается с `--live-pipeline --platform-config ... --agent-url
http://127.0.0.1:8012`, без `--demo-agent`. Он создаёт контекст
`state-<run_id>-g<state_generation>` с generation `0`, subject `all`, импортирует
уже опубликованные наблюдения, затем получает новые по SSE. При смене поколения
создаётся другой контекст; прежние записи сохраняются. Позиция сценария берётся
из State API, не из wall-clock `ts` платформы.

Этот путь использует REST платформы и не требует запуска второго импортёра через
`FIRE_PLATFORM_SCOPE`. Встроенный platform-sync агента — отдельный режим; его
`/health.platform_connected=false` не означает ошибку gateway pipeline. Его
состояние видно в `/api/pipeline/status` и в Copilot. `/health.model_configuration`
показывает фактического провайдера и ID моделей, без ключа.

Автоматическая сводка создаётся после новых импортированных данных, не чаще чем
раз в 3 секунды (`--analysis-interval 3`). Пока вопрос обрабатывается, следующий
автоматический не ставится в очередь. Пользовательские вопросы также доступны.
Briefing показывает время входных данных, задержку ответа и отставание от сценария;
трёхсекундный интервал не является гарантией трёхсекундного ответа.

## Границы анализа

Ответ использует до 20 событий из последних 500 кандидатов, максимум 24 000
символов исходных записей: последние показатели разных источников и недавние
радиосообщения. Это ограниченная выборка, не вся история. Ссылки и coverage позволяют
проверить использованные данные; отсутствие сообщения в выборке не доказывает,
что его не было. Несколько показаний нужны для вывода о тренде.

Камеры передают агенту метаданные фрагментов; визуальное распознавание не выполняется.
Видео и звук просматриваются через State API. Palisades — готовая машинная расшифровка,
которая воспроизводится вместе с аудио; новая ASR не запускается. Независимые
источники сохраняют provenance и не становятся одним реальным происшествием.

## Поведение fallback

На запрос выделено 28 секунд внутри 30-секундного бюджета UI; с резервной моделью
каждая попытка ограничена 14 секундами. Вторая получает те же данные, инструкции
и схему ответа, но свой reasoning effort. Fallback срабатывает после ошибки
API/сети, таймаута, превышения числа ходов SDK или невалидного structured output.
Успешный основной ответ и отмена не запускают резервную модель. Ошибка обеих моделей
остаётся ошибкой, без подстановки fixture-ответа. Пустой либо совпадающий с основной
`FIRE_FALLBACK_MODEL` отключает вторую попытку.

Fallback не проверяет смысловую полноту успешного ответа. Поэтому ограничения и
источники остаются видимыми даже при валидной JSON Schema.

## Проверено 12 сентября 2026

Проведены пять платных запросов через SDKEngine на одном явно синтетическом наборе
из 20 радио-, сенсорных и системных событий. Fallback и дополнительные SDK turns
на время сравнения были отключены:

| Модель | Замер ответа | Наблюдение |
|---|---|---|
| Gemini 3.1 Flash Lite, minimal | 2,006 / 1,832 с | Корректные ссылки и неизвестные; история назначения канала раскрыта неполно |
| Gemini 3.5 Flash Lite, minimal | 2,188 / 1,886 с | Один ответ сделал недостаточно ограниченный вывод об отсутствии ответа на перекличку |
| GPT-5.6 Luna, none | 4,632 с | Полнее раскрыл источники и ограничения; только один замер |

Все пять ответов прошли схему `Answer` и ссылались только на переданные IDs.
Gemini 3.1 выбран ради скорости; Luna — резерв. Это небольшой benchmark, не оценка
под нагрузкой и не измерение задержки радио-экстракции. В подключённой цепочке
предварительно наблюдалась автоматическая сводка примерно за 3 секунды; полная
приёмка непрерывного Play описывается отдельно после проверки.

На сервере отдельно проверены Platform health и публичный MCP initialize (200),
ответ ingestion со структурой `ingested` + `readings` и сохранность прежних 2111
записей Palisades после обновления только app-контейнера. State API и соседние
контейнеры не перезапускались.

Источники: [каталог моделей](https://openrouter.ai/api/v1/models),
[structured outputs](https://openrouter.ai/docs/guides/features/structured-outputs),
[reasoning](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens).
Fallback реализован в SDKEngine, включая локальную валидацию и общий таймаут.
